# AGENTS.md

Whenever you modify the code, you must also update the contents of AGENTS.md accordingly. Do not run test locally at any circumstance.

Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

## 0. Guardrails

- Never overwrite user edits between reads.
- Never restore deleted code without confirmation.
- Make the smallest fix that solves the problem.
- No scope drift: no refactors, restyles, or extras unless asked.
- Fix root causes, not symptoms.
- Use web search for unstable or version-specific behavior; cite sources.
- State assumptions; ask only when blocked.
- Briefly narrate multi-step tool usage.
- Finish the full plan once started.
- If anything in the user's request is unclear, surprising, contradictory, or looks possibly wrong, stop and ask for clarification before modifying the code. Only proceed once the user has confirmed.

## 1. Non-Destructive File Handling

**Preserve user data. Prefer additive changes over destructive ones.**

- Never delete files or directories.
- Never run destructive commands or cleanup operations that remove user data.
- Do not use `rm`, `del`, `erase`, `rmdir`, `Remove-Item`, or equivalents.
- Do not remove files just because they look temporary, generated, redundant, cached, old, or replaceable.
- Do not delete files before recreating or renaming them.
- If replacement is needed, write a new file and leave the original intact.
- If renaming fails, keep the old file and create a new one with a different name.
- If deletion seems necessary, stop and propose a non-destructive alternative first.

Default rule: when in doubt, keep all existing files.

## 2. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

## 3. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

## 4. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it - don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: Every changed line should trace directly to the user's request.

## 5. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" -> "Write tests for invalid inputs, then make them pass"
- "Fix the bug" -> "Write a test that reproduces it, then make it pass"
- "Refactor X" -> "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:
```
1. [Step] -> verify: [check]
2. [Step] -> verify: [check]
3. [Step] -> verify: [check]
```

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

# Repository Information

This file provides guidance to Claude Code (claude.ai/code) or Codex when working with code in this repository.

## Overview

CMS physics analysis toolkit for a VVV (triple vector boson) scouting search with Run 3 data. It converts NanoAOD-style ROOT files from DAS into analysis trees with jet energy corrections, trains multiclass BDT (or PyTorch NN) classifiers per tree (optionally as k-fold rotations), optimises signal regions (SRs) as score boxes, estimates QCD with an ABCD method, evaluates systematic uncertainties, and runs CMS `combine`.

**Dependencies:** ROOT (with `root-config`), C++17, correctionlib, Python 3, OpenMP (optional), XRootD for remote files.

## Pipeline Overview

1. **Pileup weights** — MC pileup-weight CSVs (`selections/weight/`, mode 1).
2. **ttbar control region and JMS/JMR** — convert the semileptonic ttbar CR with the same jet corrections (`selections/convert_ttbar_cr/`) and fit the AK8 soft-drop mass scale and resolution (`selections/jms_jmr/jms_jmr_fit.py`).
3. **Convert** — jet corrections, physics selections, the five analysis trees `boosted3`, `boosted2_resolved`, `boosted2_unresolved`, `boosted2_leptonic_1lep`, `boosted2_leptonic_2lep`, and the MC jet-variation trees (`selections/convert/`, mode 0).
4. **Mix** (optional) — shuffle per-sample entries across ROOT chunks (`selections/mix/`, mode 6).
5. **Training** — one classifier per tree, in production as 5 k-fold rotations (`selections/BDT/train.py`, mode 2), then the k-fold score cache (`selections/BDT/score_kfold.py`).
6. **Inclusive systematics** — theory (after `generator_sums.py`), pileup, JES, JER, JMS, JMR ratios without SRs, the background-uncertainty input of the SR optimiser (modes 8, 9, 11–14).
7. **SR optimisation** — `selections/signal_region/signal_region_hist.py` (mode 3) writes `signal_region.csv` per tree.
8. **QCD ABCD estimation** — `background_estimation/qcd_est.py` (mode 5) writes the combine inputs.
9. **Per-SR systematics** — the same syst scripts with the SR CSVs (modes 8, 9, 11–14).
10. **Data/MC plots** — `plotting/data_mc.py` (mode 4), `plotting/class_shapes.py` (mode 10), `plotting/sr_sensitivity.py`.
11. **Combine** — `combine/combine.C` (mode 7): expected significance and `AsymptoticLimits`.

`legacy/skim/`, `selections/b_veto/` (AK4 b-veto working points) and `systematics/` (trigger studies and the standalone ROOT macros below) are not launched through `run.py`. `systematics/find_duplicate_entries.C` chains one ROOT file or every `.root` file of a directory and reports duplicated `(run, luminosityBlock, event)` keys with multiplicities and first/last entry indices. `systematics/plot_branch_histograms.C` histograms the branches configured in its source (inputs: local files or directories, `root://` files, `/store/...` LFNs via the global redirector, or DAS datasets expanded with `dasgoclient` and filtered by `REMOTE_DATASET_FILE_NUMBER_MIN`/`MAX` on the trailing file number); C-array branches are filled with element 0 only, and it writes per-input ROOT/PDF outputs.

## Convert_branch.C output layout (consumed downstream)

`convert_branch.C` writes `{output_root}/{sample_group}/{sample}.root` (or `{sample}_0.root`, `{sample}_1.root`, … when the output exceeds `max_output_file_size_gb`), `sample_group ∈ {signal, bkg, data}` from `is_MC`/`is_signal`. Every file holds the trees of `selections/convert/branch.json`; every ROOT file convert writes uses ZSTD level 5 (setting 505; uproot needs `zstandard`). Downstream scripts discover a sample's files by globbing `{sample}.root` and `{sample}_*.root` and concatenate them in sorted order (per-file entry counts are uneven, which nothing depends on). Configured output, pileup, branch and selection paths are resolved to absolute paths at startup.

- **Batches.** `run.py mode=0` first calls `convert_branch <sample> --batch-count` with `CONVERT_REFRESH_FILE_LIST=1` (the last stdout line is the count), then `convert_branch <sample> <X>` per zero-based batch; a batch reads at most `CONVERT_FILES_PER_BATCH` files (`--slurm-files-per-job`, default 50), else `thread_count × 32`. The sorted input list is snapshotted once in `{output_root}/{sample_group}_tmp/{sample}.files` (rewritten only when missing or with `CONVERT_REFRESH_FILE_LIST=1`); every batch and the merge read the snapshot, so a growing dataset cannot shift the file-to-batch mapping. A direct invocation without a batch index processes all batches in one process.
- **Batch outputs.** `{sample_group}_tmp/{sample}_X.root` (each OpenMP thread fills its own temp file, fast-merged with `TFileMerger`), `.raw_entries`, for data `.lumis`, and last, as completion record, `.meta`: the batch's file count and input-slice hash, a configuration hash (converter binary, `branch.json`, `selection.json`, input tree, pileup CSV or lumi mask, sample metadata, and with jet corrections the `jet_pt_correction` settings and the contents of every correction and JMS/JMR file), the raw entry count, the MC sums of `weight_pu`/`_up`/`_down`, `genWeight` and `genWeight × weight_pu`/`_up`/`_down` over all events, and skipped MC files. A batch is complete only if its ROOT file opens with every configured tree (MC: also the variation trees), `.raw_entries` and `.meta` agree, and both hashes match (plus `.lumis` for data). `resume_successful_batches` (default `true`) skips only complete batches; a reprocessed batch first removes its old `.meta`.
- **Merge.** Local runs set `CONVERT_DEFER_FINAL_MERGE=1` per batch and merge once after the loop, only if every batch succeeded (merging a subset would silently drop events and luminosity; rerun to retry failed batches). `convert_branch <sample> --merge-successful-batches` merges without reprocessing and requires every batch unless `CONVERT_SUCCESSFUL_BATCHES` lists zero-based indices (manual recovery only). It refuses to run if the output directory holds files of the sample it would not overwrite, groups batch files in order into outputs of at most `max_output_file_size_gb` by basket-copy fast merging, writes each through a hidden temporary file renamed after its per-tree entry counts are checked, and only then writes the `sample.json` fields below.
- **Errors.** Remote opens are serialised with a mutex (concurrent `TFile::Open` of `root://` races) and retried five times. A data file that cannot be opened or lacks the input tree fails its batch (it would lose luminosity); an MC file is skipped, recorded in `.meta` and reported at merge time (`raw_entries` counts only processed files). A failed `GetEntry`, an unreadable or incomplete merge input, or a write error fails the batch; a per-file exception names the input file. Files whose input tree has zero entries are skipped (data lumisections still count). Each entry is first read only for the preselection branches and completely only if it passes, so read errors of rejected entries are detected only for those branches. Collections with more than `max_size` objects are truncated, with a per-file count of affected events.
- **Lumi mask.** `lumi_mask` (golden-JSON file relative to the convert config) is applied to data before the preselection; only accepted entries count in `raw_entries`. The lumisections passing the mask are recorded from each file's `LuminosityBlocks` tree (fallback: the Events entries), and the merge writes their union to `{output dir}/{sample}_processed_lumis.json` for `brilcalc lumi -i` and `selections/weight/make_data_pileup.sh`. `run.py` still exports `CONVERT_GOLDEN_JSON`, which convert does not read.
- **`sample.json` write-back.** After every output file is written, the merge writes `raw_entries` (sum of `tree_name` entries), for MC `weight_pu_mean`, `weight_pu_up_mean`, `weight_pu_down_mean` (all-event sums / `raw_entries`) and the signed sums `sum_genweight`, `sum_genweight_pu`, `sum_genweight_pu_up`, `sum_genweight_pu_down` over all processed generated events (`genWeight` is read for every MC entry before the preselection); it fails if `sum_genweight_pu` is not positive. With `update_raw_entries: false` nothing is written. `convert_branch <sample> --update-genweight-mean` (MC) reads only the `Runs` trees serially and writes `genweight_mean = Σ genEventSumw / Σ genEventCount` (unreadable files skipped with a warning; it also prints `Σ genEventCount`). Both writers hold an exclusive `flock` on `src/sample.json.lock` and write through a per-process temporary file, so parallel jobs cannot lose updates; a missing field is inserted after `raw_entries`.
- **Recovery.** [selections/convert/check_conversion.py](selections/convert/check_conversion.py) inspects the newest merge log, batch files and merged outputs per sample (a batch is valid only with `.meta`, and `.lumis` for data; the hashes are checked by `convert_branch` at merge time), reports `MERGE_FAILED` for a log with `Missing or incomplete batch`, `Batch collection error`, `Output error`, `raw_entries update error` or `Processed-lumi error`, checks every variation tree and its branches, and prepares remerge / resubmit / reprocess jobs that pass `CONVERT_FILES_PER_BATCH` and use the newest `convert_branch_<hash>` binary (the merge rejects batches of another binary).

`selections/convert/branch.json` writes, for every tree, per-AK8 `WvsQCD`, `VvsQCD` (`Xud + Xcs + Xqq + Xbb + Xcc + Xss` of `scoutGlobalParT_prob` over that sum plus `QCD`) and `ZvsQCD` (`Xbb + Xcc + Xss + Xqq`) scores, the summaries `ScoutingFatPFJetRecluster_{WvsQCD,VvsQCD}_{sum,max}`, and the AK4 b-tag summaries `ScoutingPFJetRecluster2_scoutUParT_probb_{max,max_pt,sum,second_max,second_max_pt}`. The model input list (`selections/BDT/branch.json`) is independent of the convert outputs.

`selections/mix/mix.C` writes a shuffled mirror `{sample_group}_mixed/` with the original chunk filenames and per-chunk entry counts: it scans the chunk entry counts (OpenMP after a serial ROOT warm-up), chains the chunks, applies a deterministic per-tree block shuffle seeded by `random_state` (with a random cyclic rotation inside each block; block size `clamp(total_entries / 512, min_block_entries, max_block_entries)`, defaults 32 / 4096), clones each output chunk from the `TChain` itself so branch addresses follow file boundaries, and validates per-chunk and total entry counts. Read it with `input_pattern = {input_root}/{sample_group}_mixed/{sample}.root`; the production BDT config reads the unmixed `dataset_hybrid_leptonic`.

## Jet energy corrections and jet systematics

`convert_branch.C` corrects the AK4 (`ScoutingPFJetRecluster2`) and AK8 (`ScoutingFatPFJetRecluster`) jets (plain PF jets matching AK4PFHLT/AK8PFHLT) and the MET in `processInputFile` after the event preselection and before any runtime collection, tree selection or output reads the event. `JetPtCorrectionConfig` holds the `jet_pt_correction` block (`validateJetPtCorrectionConfig`), `CorrectionConfiguration` one configuration (nominal or a variation), and `JetPtCorrector` the chain:

- `initialize` loads the Winter24HLT_V1 MC-truth compound JEC (`jec_ak4_name` / `jec_ak8_name`, L1L2L3Res) and L1FastJet (`jec_ak4_l1_name` / `jec_ak8_l1_name`) from `selections/convert/jec/Run3Winter24/`, the JER `PtResolution` / `ScaleFactor` (`jes_jer_file`, JME-POG `2024_Summer24/jet_jerc.json.gz`) and `JERSmear` (`jer_smear_file`), checks every correction's inputs, reads JMS, JMR, their errors and the MC W-peak `sigma / mu` from `jms_jmr_results_file` when `apply_jms_jmr`, and builds the MC configurations (nominal plus `variations`; with the validation key `debug_nominal_configuration` only that configuration, written to the nominal trees) and one data configuration.
- `prepareEvent`: AK4 raw pT and mass = stored × (1 − `rawFactor`), and the stored AK4 factor (the production Winter24HLT_V1 JEC) is the nominal AK4 correction; AK8 is stored raw and gets the compound JEC. `recoverRho` recovers the event rho (not stored): the compound falls with rho up to the L1FastJet clamp `kRhoRecoveryMax` (70 GeV); the first AK4 jet with a solution (Illinois regula falsi, continued by point reflection) gives rho, and every jet must reproduce its stored factor within `kRhoRecoveryTolerance` (0.5 GeV), else `consensusRho` also tries the JEC bins a `kJecBinEdgeProbe` shift in eta or phi reaches and requires one solution per jet within the tolerance of their median. Jets at the L1FastJet floor or without rho dependence carry no rho; an event without a common rho, or with jets but no usable AK4 jet, is an error naming run:lumi:event. Per jet it then computes the L1FastJet factor, the MC JER smearing factors for the `nom` / `up` / `down` scale factors (`JERSmear` with `GenPt = −1`, `EventID` as `int`, resolution rho clamped below `kJerRhoUpperEdge` = 52.05), the AK8 soft-drop factor (compound / L1FastJet), the AK8 JMR random number (`jetGaussian`, a hash of event and jet), and the Type-1 jet set (muon-subtracted corrected pT > 15 GeV, `chEmEF + neEmEF` < 0.9).
- `applyConfiguration`: pT and mass = raw × JEC × (MC: JER smearing × JES factor); AK8 soft-drop mass = raw × soft-drop factor × the same variation × (MC with JMS/JMR: JMS × (1 + N × sqrt(max(JMR² − 1, 0)) × sigma/mu)); Type-1 MET = raw MET − Σ muon-subtracted raw pT × (factor − L1).
- `nominal_correction: scouting_to_offline` keeps the legacy response SF of `corrections_file` on the stored jets with the b/light (MC, `partonFlavour` ±5 is b) or btag/nobtag (data) category; off by default.

`processInputFile` builds the input collections and the runtime collections independent of the jet corrections (`jetDependentCollections`; currently `w_quarks`, `wz_had_quarks`) once per event, then for each configuration copies the event variables, writes the corrected MET, rebuilds the AK4/AK8 inputs and the jet-dependent runtime collections, and evaluates that configuration's trees. `addVariationTrees` (MC only) appends one `<tree>__<variation>` tree per nominal tree and variation, booking that tree's `variation_branches` (`TreeConfig::keptBranches`, unbooked outputs `kNoBranch`) and evaluating only the scalar outputs they need (`neededScalarOutputs`); variation trees carry no theory-weight branches, share the nominal trees' resolved expressions, and are identical event by event to the nominal trees of a conversion with `debug_nominal_configuration` set to that variation. Without `jet_pt_correction` (or `enabled: false`) there is one configuration on the uncorrected variables. `requirePreselectionWithoutCorrectedInputs` rejects a preselection reading the corrected MET scalars; the keys `variation`, `jes_unc_name`, `jer_rho_fallback` of the removed one-conversion-per-variation scheme are rejected (`config_{jes,jer}_{up,down}.json` are kept for reference only). `branch.json` must declare the AK4 floats `pt`, `eta`, `phi`, `mass`, `area`, `rawFactor`, `muEF`, `chEmEF`, `neEmEF`, the AK8 floats `pt`, `eta`, `phi`, `mass`, `msoftdrop`, `area`, and the scalars `ScoutingMET_pt`, `ScoutingMET_phi`, `run`, `luminosityBlock`, `event`. `variation_branches` must list, per tree, every BDT feature, threshold and decorrelation branch plus `run`, `luminosityBlock`, `event`, `genWeight`, `weight_pu` (the jet syst scripts stop on a missing branch).

`run.py`'s `compile_binary()` finds correctionlib via `python3 -c "import correctionlib"` (a user-site copy takes precedence over CMSSW's) and links it with an rpath, so the binary needs no `LD_LIBRARY_PATH`.

`selections/{jes,jer,jms,jmr}_syst/<syst>_syst.py` wrap `jet_variation_common.run(syst, script_dir, config_env)` (`selections/jet_syst_common/`): per MC sample and tree they sum the signed product of the required `event_reweight_branches` (`genWeight × weight_pu`; the former `weight_branch` is not read) on the nominal tree and on `<tree>__<syst>_up` / `_down` of the same files, inclusive and per SR, and write `<syst>_syst_yields.{json,csv}` (`nom_sum`, `n_events`, `<syst>_up`, `<syst>_down`, `regions`, and per sample and tree the `sr_csv_hash`). For k-fold models a variation-tree event is scored with the fold of the nominal entry with the same (run, lumi, event) in that file, events without one by `data_fold`. `merge_shards.py` merges per-sample shard outputs; the removed `input_root_up` / `input_root_down` keys are rejected.

**Common rules of the syst scripts (theory, pileup, jet):** SR membership uses the tree's model (k-fold: each event with its fold's model), the `signal_region.csv` boxes and every BDT `selection.json` threshold with qcd_est's `_mask_from_cond` semantics (sentinel values fail), so each SR is the ABCD A region; a region with fewer than `min_region_events` (10) nominal MC events takes the inclusive ratios (`fallback_to_inclusive`); a variation without events in a region has ratio 0; missing files, trees, branches or configured inputs are errors; a tree without `signal_region_csv` gets inclusive ratios only (the inclusive JSONs of the SR optimiser come from `config_inclusive.json` in each syst directory: the default config without `signal_region_csv`, writing to `output/inclusive/`). A sample outside the k-fold training (not in `class_groups`) is an error in the k-fold region path (`KFoldModels.check_files`); leave it out of `submit_samples`. Every per-SR entry records `sr_csv_hash` (first 13 hex digits of the SHA-256 of the SR CSV), which combine checks against qcd_est's `metadata/sr_csv_hash`.

## Generator weights

Every MC weight builder uses signed, absolutely normalised weights (user decision 2026-10-08, kept in the 2026-10-13 merge with Jan's branch; shared code `selections/mc_weight_common/mc_weights.py`):

    w = lumi × xsection × genWeight × weight_pu / S × N_tree / N_read

- `S` = `sum_genweight_pu` of `src/sample.json`, the sum of `genWeight × weight_pu` over every processed generated event (convert merge), so selected events carry the selection efficiency and negative NLO weights enter with their sign. `N_tree / N_read` scales a read subset to the whole tree (1 for full reads). `WEIGHT_DENOMINATOR_KEYS` maps each supported reweight-branch product to its `sample.json` sum (`(genWeight, weight_pu)` → `sum_genweight_pu`, the pileup variations, `(genWeight,)` → `sum_genweight`); any other product, an empty list, or a missing or non-positive sum is an error. Configs list `event_reweight_branches: ["genWeight", "weight_pu"]`.
- Users: `train.py` (and its class budgets, which use `raw_entries` only to allocate events), `kfold.py` `read_sample` and `score_kfold.py` (pre-lumi `xsection × raw_w / S`, every entry read; `read_sample` takes the sample's `src/sample.json` entry), `signal_region.py` / `signal_region_hist.py`, `qcd_est.py`, `data_mc.py`, `class_shapes.py`, `sr_sensitivity.py` (through qcd_est / kfold), `jms_jmr_fit.py`, `theory_syst.py`, `pileup_syst.py`, `jet_variation_common.py`. Jan's `genweight_mean × weight_pu_mean` normalisation (`selections/BDT/gen_weight.py`) was replaced everywhere; that file stays in the repository but nothing imports it. `genweight_mean` (from the `Runs` trees) is a cross-check of `sum_genweight / raw_entries`.
- Classifier training uses `|w| × Σw / Σ|w|` per sample and split (`mc_weights.training_weights`; XGBoost accepts only non-negative weights); a sample whose signed sum in a split is not positive gets a warning and zero training weight, its physics weights unchanged. Every physics output and saved reference weight is signed.
- Pileup ratios use their own sums: `pu_up = [Σ g·pu_up / S_up] / [Σ g·pu / S]` (same for down). Jet-variation ratios are signed sums on the nominal and variation trees (normalisation cancels). Theory ratios: see "Theory systematics".
- `qcd_est.py` writes negative SR yields (possible with signed weights) to the ROOT file as 0 with a warning, keeping their `Σ w²`. The MC pileup profile of `weight.C` is unweighted.

## Theory systematics (`theory_syst.py`, mode 8)

- PDF: symmetric-Hessian quadrature (`pdf_uncertainty_method`, default `hessian_symmetric`; `mc_replica` optional); α_s is folded in only when `nLHEPdfWeight >= 103` (older files: non-placeholder `LHEPdfWeightAlphaS`), otherwise a warning and `alphas_available: false`. Scale: 7-point envelope without `LHEScaleWeight` indices 2 and 6 (an 8-entry set is stored in the 9-entry layout with 1.0 at index 4). PS: `PSWeight` = `[0] isr.murfac=2.0; [1] fsr.murfac=2.0; [2] isr.murfac=0.5; [3] fsr.murfac=0.5`, `ps_*_up` = murfac 0.5 and `ps_*_down` = murfac 2.0 in every region (`data_mc.py`'s theory band uses the same pairing). `convert_branch.C` fills `LHEPdfWeightAlphaS` with 1.0 when the PDF set has no α_s members, stores `nLHEPdfWeight`, `nLHEScaleWeight`, `nPSWeight`, sizes the theory buffers per file, and writes `genWeight` once per tree.
- Acceptance-only normalisation (Jan, 2026-10-09): each member's selected-event ratio `Σ w·w_i / Σ w` (signed `w = genWeight × weight_pu`) is divided by its value over all generated events, `Σ genWeight·w_i / Σ genWeight`, before the envelope / quadrature (`_generator_sums`, entries flagged `generator_normalised: true`), so the variations change only the selection efficiency; the inclusive cross-section uncertainty is the per-process `xsec_<process>` lnN of combine (`combine/xsec_unc.json`). The required config key `generator_sums_json` must hold every processed theory sample.
- [selections/theory_weights/generator_sums.py](selections/theory_weights/generator_sums.py) `[sample ...]` (config `THEORY_CONFIG_PATH`) reads the `Runs` trees of the files of the conversion snapshot `{input_root}/{sample_group}_tmp/{sample}.files` (remote, serial, five retries, unreadable files skipped and listed), averages `LHEScaleSumw` / `LHEPdfSumw` / `PSSumw` weighted by `genEventSumw`, maps them to the per-event layout of `convert_branch.C` (101 PDF members, α_s at source indices 101/102, 9 scale entries, 4 PS entries, missing entries 1.0) and writes `<dirname(generator_sums_json)>/generator_sums/<sample>.json`; `--merge` collects them into `generator_sums_json`.

## Model Training Details (`selections/BDT/train.py`, mode 2)

**Inputs and outputs.** Trains on the samples of `class_groups` (number of classes inferred; a class whose samples all have `is_signal` is a signal class). `model_type` `bdt` (XGBoost) or `nn` (PyTorch MLP, per-tree `{tree}_nn` blocks; PyTorch is imported only then). Per tree, `output_root` (e.g. `selections/BDT/boosted3/`, k-fold: `fold<r>/`) receives `{tree}_model_stage1.json` / `{tree}_model.json` (NN: `.pt`), copies of `config.json`, `branch.json`, `selection.json`, `test_ranges.json`, the prediction references `test_reference_signal_region.npz`, `test_reference_qcd_est.npz`, `test_reference_qcd_est_full.npz` (with `entry_index`, the global entry index of each row) and, with an eval split, `eval_reference_signal_region.npz`, plus the diagnostic plots and `branches/` (normalised per-class input distributions after the full thresholds and clipping, before the log transform). Each reference stores feature order, sample order, class labels, pre-lumi signed physics weights, probabilities and per-array tolerances; downstream checks multiply the stored weights by their `lumi`. Downstream scripts load models through `selections/BDT/model_io.py` (format from the copied `model_type`) and apply the softmax explicitly.

**Splits.** Each sample's concatenated entries are split into train `[0, a)`, eval `[a, b)`, test `[b, N)` (`train_fraction`, `eval_fraction`; production 0.6 / 0.2); `test_ranges.json` stores the eval/test segments. `entries_per_sample`, `eval_entries_per_sample` (default `test_entries_per_sample`) and `test_entries_per_sample` cap the events read from the start of each range. `train_events_per_class` (a number for every class or `{class: budget}`; production `{"Top": 3000000}`) replaces the training cap of the listed classes by a budget shared among the class's samples in proportion to `xsection × N_tree / raw_entries × training-weight scale` (water-filling, at least one block per sample), read as random 8192-entry blocks seeded by `random_state` and tree/sample; `test_ranges.json` records only the train range. `eval_events_per_class` / `test_events_per_class` (production 0) do the same for eval/test without the training-weight scales and store `{split}_random_blocks` so the downstream loaders can rebuild a stale split. The eval split monitors early stopping and the learning-rate schedule (the loss-history key stays `"test"`, plots label it `Eval`); the test split serves the diagnostic plots and, without k-fold, the downstream yields. Every sample needs at least one entry in every split. Training events are shuffled; eval/test keep their order.

**k-fold** (`kfold` = K ≥ 3, requires `train_fraction` = (K − 2)/K and `eval_fraction` = 1/K; production 5): block j = entries `[N j / K, N (j + 1) / K)`; rotation r trains on the other K − 2 blocks (budgets draw over their union, `_random_block_segments_multi`), monitors on block r − 1 and tests on block r, written to `<output_root>/fold<r>`, whose `test_ranges.json` adds `kfold`, `fold`, `monitor_fold` and per sample `train_intervals`, `block_bounds` and the file list with entry counts. `BDT_FOLD=r` selects one rotation (else all K run in turn); `BDT_TREES` (comma-separated) restricts the trees. [selections/BDT/kfold.py](selections/BDT/kfold.py) `KFoldModels` checks that the rotations share one configuration and the same files and blocks, maps an MC event to its fold by global entry index (`fold_of_index`, `check_files`), scores data and never-trained events by event number modulo K (`data_fold`), reads and scores a whole sample (`read_sample`) and loads the cache (`load_scores`). [selections/BDT/score_kfold.py](selections/BDT/score_kfold.py) `<tree root> [sample ...] [--branches a,b]` writes `<tree root>/kfold_scores/<sample>.npz` (entry index, fold, class, probabilities, pre-lumi weight `xsection × raw_w / S` with every entry read, every threshold / decorrelate branch plus `--branches`, for events passing the non-msoftdrop thresholds) after a strict check of every fold's probabilities against the matching rows of that fold's `test_reference_qcd_est_full.npz` (stored tolerances, no relaxed path); `submit_score_kfold.sh <tree root> [--after ids] [--branches ...] [--mem 16G] [--time 04:00:00]` submits one job per sample. The cache records a fingerprint of the K model files (refused after retraining) but neither the weight convention nor the sample metadata: after a change of `xsection` or `sum_genweight_pu`, and for every cache written before the 2026-10-13 merge (old `genweight_mean` normalisation), rescore. k-fold consumers (detected by `fold0/test_ranges.json` with `kfold`; configs from `fold0`): `signal_region.py` / `signal_region_hist.py` (`OPT_SPLIT = kfold`, every cached MC event, all thresholds), `qcd_est.py` (`load_kfold_test_data`, non-ABCD thresholds), the syst scripts (fold models), `data_mc.py` (MC by fold, data by `data_fold`), `sr_sensitivity.py` (`read_sample`, data by `data_fold`), `combine.C` (`class_groups` from `fold0`). So SR optimisation and yields use the same events (user decision).

**Weights.** Physics weights per split as in "Generator weights" (`weight_physics`, signed, pre-lumi), frozen before any threshold cut; the reweight branches are read on raw values, consumed for `raw_w` and dropped (missing branches raise `KeyError`). Internal training weights (`weight`): rectified per sample, then the per-tree scales `qcd_ht_training_weight_step` (`1 + rank × step` in increasing configured QCD HT order) and `training_sample_weight_scales` (`{sample: factor}`, 0 removes a sample from training and monitoring only), then class balancing after the threshold filter within each split (each class total `N_filtered / N_classes`, preserving the within-class sample shares; `class_balance_power` p ∈ [0, 1] sets class totals ∝ (unbalanced total)^(1 − p) instead), then `training_weight_cap` (0 = off, else ≥ 1: every weight in the fitted and monitored splits limited to `cap × class mean` with the class total kept by rescaling; production 20, against a few very heavy low-HT QCD events). Plots and physics weights are never capped or scaled.

**Thresholds.** `filter_X` inspects only the branches of the active threshold dictionary (sentinels `< -990` fail there). Threshold and decorrelate branches missing from `branch.json` are read too; threshold-only ones are dropped after filtering, so the model inputs are exactly `branch.json` (decorrelate branches go to `Z`). The training view drops the thresholds of decorrelate branches, except that a `ScoutingFatPFJetRecluster_msoftdrop_*` decorrelate branch with a threshold keeps a loose `(0, decor_msoftdrop_training_max)` window (production 250); it serves training, early stopping, the decorrelation state and class balancing. The full evaluation view (all thresholds) serves ROC, scores, importance, `feature_corr.pdf`, the branch plots and `test_reference_signal_region.npz`.

**Two stages.** With non-empty `decorrelate` and `decor_lambda > 0`: BDT stage 1 is native `multi:softprob` (`n_estimators`, `learning_rate`), best round by monitored `classification_loss`; stage 2 resumes from the stage-1 best model for `n_estimators_decorr` rounds at `learning_rate_decorr` with the custom objective, best round by monitored `total_loss = classification_loss + decorrelation_loss`. NN: stage 1 `objective_loss = weighted_CE`, stage 2 adds the scaled smooth-CvM term, class-balanced mini-batches (`batch_size` = total events per batch) with sampling-corrected weights for `backward()`, epoch-end eval-mode `train/test_objective_loss` for selection; AdamW `weight_decay` is not a logged loss. Without decorrelation stage 1 is promoted to the final model. With `lr_reduce_patience > 0` and `min_learning_rate > 0` stale rounds halve the learning rate down to the floor and early stopping (`early_stopping_rounds`) applies only at the floor (production floor 0.005, patience 4). BDT `classification_loss = Σ w·(−log p_true)`, `mlogloss` its weighted mean, `regularization_loss` reconstructed per tree from `gamma`, `reg_lambda`, `reg_alpha` on unshrunk leaves (`leaf / eta`). The decorrelation scale is calibrated once from the stage-1 best model: BDT `(cls + reg) / max(raw_decor, ε)`, NN `cls / max(raw_decor, ε)` with the same mini-batch smooth-CvM.

**Decorrelation loss.** `smooth_cvm` (default; BDT and NN) acts on the QCD events only (classes whose name contains `qcd`; training stops without one) and, for every class probability `p_k`, penalises the dependence of its log-odds `log(p_k / (1 − p_k))` on each decorrelate variable, using sigmoid-smoothed bins (`decor_n_bins`, `decor_bin_tau_scale`) and probability thresholds (`decor_n_thresholds`, `decor_score_tau`; `decor_tail_aware` adds `decor_tail_n` log-spaced thresholds per tail down to `decor_tail_min_prob`), with event weights; the BDT gradient goes through the softmax with a Gauss–Newton diagonal Hessian. `decor_eff_normalize` (smooth-CvM only) divides each threshold's term by `max(ε(1 − ε), decor_eff_norm_floor)` of its global QCD efficiency, including the derivative of that factor, so tail thresholds get weight. Legacy `cvm` (BDT only) keeps the hard-bin own-class raw-margin loss. Smooth-CvM state is prepared per QCD class once; metric-only evaluation skips gradient/Hessian work; `_smooth_cvm_shared_terms` shares the per-class sigmoid terms and uses `np.einsum` (keep float64: float32 changes the loss by ~30%). Production (`kfold_finedecor` settings): `decor_lambda` 2, `decor_n_bins` 10, `decor_n_thresholds` 15, `decor_tail_min_prob` 2e-4, `decor_tail_n` 10, `decor_eff_normalize` with floor 1e-4, `max_depth` 4, `min_child_weight` 50, `learning_rate_decorr` 0.05, `n_estimators_decorr` 1500, `training_weight_cap` 20.

**Plots and logs.** Comparison plots exist per stage as `*_cls.pdf` / `*_decorr.pdf`: `importance` (BDT gain, NN permutation importance on `permutation_importance_events`), `roc_*` (per signal class against every background, test solid, train dashed; without a signal/background split one per class), `score_*` (per signal–background pair), `decor_corr_{train,test}` (weighted Pearson correlations of class probabilities with the decorrelate branches: own probability per class, plus `QCD: p(k)` rows), `decor_score_vs_branch` and `decor_branch_shapes_by_signal_score` (training-view test events, decorrelate branches after the training-view thresholds and clipping, before the log; efficiencies from `decor_efficiencies`). Loss plots (`loss_mlogloss/classification/total.pdf` or `loss_weighted_ce/objective.pdf`, plus `loss_decorrelation.pdf`) mark the stage boundary. XGBoost uses `min(32, len(os.sched_getaffinity(0)))` threads; the trainer logs the CUDA build flag, a failed `device=cuda` stage before its CPU rerun, and each stage's device. Keep the memory patterns of `train.py` (detached copies, unfiltered test split by reference only until the references are written, column-wise clipping, early release of large arrays).

**Training studies.** [selections/BDT/study_boosted3/](selections/BDT/study_boosted3/) holds Jan's boosted3 studies, summarised with formulas and numbers in [significance_review.md](selections/BDT/study_boosted3/significance_review.md): `make_study.py [variant ...]` writes per variant a BDT and an SR-scan config (`VARIANTS`, `GLOBAL_CHANGES`, `VARIANT_TREES`, `DROP_SAMPLES`, `LOW_HT_QCD`), `submit.sh [variant ...]` submits training plus a dependent SR scan and `evaluate.py <variant>` (`STUDY_EXCLUDE`, `STUDY_AFTER`, `STUDY_HOLD`), `evaluate.py --table` compares variants; `abcd_viability.py`, `abcd_closure.py build|analyze` and `mass_fit.py build|ratio|models|bias-submit|bias-summary` study the per-SR ABCD closure and a jet-mass fit; `sr_granularity.py submit|summary|abcd [--grid-tag ...] [--control ...] [--nonclosure ...] [--exclude-low-ht] [--abcd-aware-scan]` runs grids of SR scan, `qcd_est.py` and `combine.C` (its own binary under `sr_granularity/`). Findings that set the production choices: `max_depth` 4 / `min_child_weight` 50 halved the overtraining gap; the HT < 400 GeV QCD samples (`qcd_ht40to70` … `qcd_ht200to400`) carry very heavy events that dominated the ABCD transfer factor (pileup double counting), so they stay in the training but are excluded from every physics yield (`exclude_samples` of the SR scan, `qcd_est.py`, `data_mc.py` / `class_shapes.py`); the per-SR ABCD closes within MC statistics with the 20–50 GeV `msoftdrop_1` control window and a 20% non-closure; choosing the SRs with the ABCD-aware uncertainty improves the per-SR ABCD significance. Study results predate the 2026-10-13 merge and used Jan's weight normalisation.

## Signal Region Optimizer (`signal_region_hist.py`, mode 3)

`run.py` mode 3 runs `selections/signal_region/signal_region_hist.py` (config: first argument, else `SR_HIST_CONFIG_PATH`, else `config.json`; it sets `SCAN_CONFIG_PATH` to the same file before importing `signal_region.py` as `sr`, which supplies loading, thresholds, standardisation, inference, the reference check, `asimov_z`, reporting, CSV and plots). Per-tree configs `config_hist_<tree>.json` write `output/<tree>_hist/` (read by `background_estimation/config_<tree>.json`, the syst configs and `combine`); `config.json` is the `boosted3` one. `config_hist_decorr3_tuned.json`, `config_minbkg50_fat3_v2.json` and `config_tailaware_fat2.json` are older study configs.

- **Inputs.** k-fold `bdt_root`: every cached MC event passing all thresholds (`sr.load_kfold_inputs`); with `abcd_uncertainty` (ABCD mode, k-fold only), the cache with every threshold but the ABCD branch's, split into the scan events (ABCD branch passing) and the control events (inside `control_window`, exclusive, of its fail region). Otherwise `OPT_SPLIT` (eval, else test) from `test_ranges.json`, with the prediction checked against `{OPT_SPLIT}_reference_signal_region.npz` (`validate_prediction_reference`, default and production true). `exclude_samples` drops the named samples (production: the four HT < 400 GeV QCD samples).
- **Region background and variance** (as the combine cards). `B` = background MC (`w_bkg_fit`); in ABCD mode its QCD part is the prediction from the box's control events, `C_box^QCD × TF` (`abcd_qcd`; `TF` = QCD scan-event yield / QCD control yield over all scores, qcd_est's complement-mode B/D), as `qcd_est.py` per_sr and combine's control-region fit. `Z_A(S, B, V)` = `sr.asimov_z` (G. Cowan, "Discovery sensitivity for a counting experiment with background uncertainty"; `za2`), `V` (`background_variance`) = `Σ_k (Σ_c δ_{k,c} B_c)²` + MC `Σ w²` of `w_bkg_fit` + zero-count floor + ABCD variance:
  - `δ` (`background_syst_shifts`, nuisance row × background class, with row names) follows the rows of the cards: `lumi` (`lumi_unc`), `trigger` (`trigger_unc`), `theory_pdf`, `theory_ps_isr`, `theory_ps_fsr`, `pileup`, `jes`, `jer`, `jms`, `jmr` (each correlated across the classes) and one `theory_scale_<class>` and one `xsec_<class>` row per class (combine's per-process rows). Ratio rows come from the inclusive `background_syst_jsons` (`theory`, `pileup`, `jes`, `jer`, `jms`, `jmr`, all required): the class ratio per up/down pair is the yield-weighted mean of its samples' ratios (samples without theory weights count with 1 for theory; a missing entry is skipped only for a non-positive yield, else an error), `δ = u if |u| ≥ |d| else −d` with `u = R_up − 1`, `d = R_down − 1`. The xsec row of a class is the mean of its samples' `xsec_unc_json` values (fnmatch patterns as `combine.C`; a sample without a pattern, or matched by patterns of different values, is an error) weighted by their positive yields. In ABCD mode the QCD classes get no row (the data-driven QCD of the cards has none). Rows without any shift are dropped; a shift ≤ −1 is an error. Signal uncertainties do not enter.
  - `zero_count_floor` (production true): per background class without MC events or with a non-positive sum in the box, `α_c²` with `α_c` = median |w| of the class over all scan events (combine's `gmN 0 α`); in ABCD mode the QCD has no floor and no MC `Σ w²`.
  - ABCD variance (`abcd_variance`; production `ScoutingFatPFJetRecluster_msoftdrop_1`, [20, 50], 0.2): `TF² × (C + Σ w² of the non-QCD background MC in the control box) + (nonclosure × predicted QCD)²`, `C` the expected control count of the box (every process).
- **Search.** `find_regions` (coarse beam search on `coarse_bin_width` grids, `qcd_coarse_bin_width` on the QCD axis, `target_n` disjoint re-seeding passes; optional `merge_score_axes`) → `dedupe_by_event_mask` (every candidate shrunk with `event_preserving_shrink` to the smallest box holding the same geometry points, i.e. the scan events and in ABCD mode also the control events, found with the per-axis sorted index `_AxisIndex` instead of full masks; identical point sets merged via a blake2b digest of the point indices, smallest box kept) → `select_regions_openmp` (`openmp_region_select.cpp` beam incumbent plus branch-and-bound, built into `output_dir/.openmp/`, used when `max_threads > 1` and N ≤ 16) or the Python bitset `select_branch_bound` (greedy incumbent stops at N, also for N = 1), maximising `Σ Z_A²`; `branch_bound_time_limit_seconds` (default and production 14400), `branch_bound_max_nodes` (0 = unlimited); a stopped search logs the upper-bound certificate → exactly N or an error (`require_exact_n_regions`) → joint stage (`joint_refine_selection`: one region at a time is replaced by the compatible candidate, among the `JOINT_SWAP_POOL` = 256 candidates of highest Z_A, that most increases `Z_joint`, for at most `JOINT_SWAP_PASSES` = 10 passes; the candidates are indexed in the selectors' order, sorted by −Z²) → `fine_refine_selected` (`fine_bin_width` / `qcd_fine_bin_width` within `fine_refine_window` / `qcd_fine_refine_window`, every alternative checked by `evaluate_region` with all minima `min_bkg_weight`, `min_signal_weight`, `min_*_entries`, never lowering Z_A; the refined set is kept only if `Z_joint` does not drop) → `place_boundaries` (shrink to the points, then raise signal-axis upper bounds and lower background-axis lower bounds into space without scan or control events up to the nearest point or region; the point sets stay unchanged; an axis is a signal axis when all classes it sums are signal) → `check_no_overlap` (geometry and points) → `build_top_bins` (`S`, `B` = the objective's background, `B_err` = its MC statistical error, `significance` = Z_A with numerical-derivative error, `significance_stat`, `background_variance`; in ABCD mode a log line per bin with the predicted and the MC QCD).
- **Joint significance** (`joint_z`, `region_components`). All regions in one likelihood: Asimov counts `n_i = S_i + B_i`, background `ν_i = γ_i [Σ_c b_ci Π_k (1 + δ_kc)^θ_k + q_i (1 + f_nc)^θ_nc]` with `b` the per-class MC background, `q` the predicted QCD (ABCD mode), `θ_k ~ N(0, 1)` per row of `δ` and `θ_nc` for the ABCD non-closure, all correlated across the regions as in the cards (combine's `qcd_abcd_nonclosure_<channel>`), and `γ_i ~ N(1, v_i / B_i²)` for the uncorrelated variance `v_i` (MC `Σ w²`, floor, `TF² × C` statistics); `q0 = 2 Σ_i [n_i ln(n_i/ν_i) − n_i + ν_i] + Σ θ² + Σ (γ_i − 1)² B_i²/v_i`, minimised over θ with scipy L-BFGS-B and every γ_i profiled in closed form; `Z_joint = sqrt(q0)` (for one region without correlated rows the Gaussian-constraint counterpart of Z_A). The per-tree objective covers one channel; correlations between channels enter only in combine. `Z_joint` and `sqrt(Σ Z_A²)` are logged, and `joint_significance` is stored in the selection summary.
- **Output.** `signal_region.csv` (one row per SR, `bin_index`, `{axis}_low` / `{axis}_high` half-open bounds, `significance`, `significance_stat`; downstream reads only `bin_index` and the bounds), the report and the score plots of `signal_region.py`. Production keys also include `min_bkg_weight` 5, `min_bkg_entries` 0, `score_axes` `all`, and `xsec_unc_json` (`../../combine/xsec_unc.json`, required). The final sensitivity is the combine result.

## `signal_region.py` (library and standalone scan)

`signal_region.py` (config `SCAN_CONFIG_PATH`, default `config.json`) is mainly the library of mode 3: `OPT_SPLIT` (`kfold` / `eval` / `test`), `load_split_data(branches, split)` (weights of "Generator weights" × `lumi`; stale file paths rebuilt from the current files with the training-time fractions, caps or stored random blocks; `load_test_data` kept for study scripts), `load_kfold_inputs`, `filter_X`, `standardize_X` (clip and log in the stored dtype), `_compare_prediction_reference` (strict: features, sample order, class labels, weights × `lumi`, probabilities with the stored tolerances), `asimov_z` / `asimov_z_with_error` (`σ_B` held fixed in the finite-difference error), `write_signal_region_csv` (adds `significance_stat` when the bins carry it), and the plots (`sr_score_*.pdf`, `scores[_no_regions][_radial_equalized].pdf`: class probabilities projected on a regular polygon with the shared class palette). Run directly, it performs its own candidate-pool scan over `score_axes` (quantile edges, beam coordinate search, compatibility expansion, local event-threshold refinement, event-mask deduplication, global OpenMP/Python branch-and-bound, empty-bin expansion; keys in "Configuration Architecture") with `Z = asimov_z(S, B, Σ w²_bkg)` and always validates the reference.

## QCD ABCD estimation (`qcd_est.py`, mode 5)

`background_estimation/qcd_est.py` (config `QCD_EST_CONFIG_PATH`, default `config.json`; per-tree `config_<tree>.json`, `config.json` = boosted3) reads the copied configs of `bdt_root` (k-fold: `fold0`) and `signal_region_csv`, and the score axes from its `{axis}_low/_high` columns.

- **Events.** k-fold: the score cache (`load_kfold_test_data`, non-ABCD thresholds applied while loading; `a_region_shape_branches` must be in the cache). Otherwise the test split with the weights of "Generator weights" (reading `model_branches ∪ thresholds ∪ decorrelate ∪ a_region_shape_branches`), the configured `abcd_branches[tree]` thresholds removed before inference, batched XGBoost inference (`inplace_predict`, `DMatrix` fallback) with `min(32, CPU affinity)` threads (`os.cpu_count` fallback), and a strict check against `test_reference_qcd_est_full.npz` (sample and class labels and weights × `lumi` on all rows, probabilities of the events passing the non-ABCD thresholds, `proba_rows`), else the filtered `test_reference_qcd_est.npz`; keep the timing/size logs of this validation. `exclude_samples` (must be in `class_groups`) leaves samples out of every yield and region, written as zero bundles; every `class_groups` sample gets a `samples/*` bundle.
- **Regions.** QCD = classes whose name contains `qcd`. A = union of the SR boxes with every ABCD branch passing; B = outside with all passing; C = inside with all failing; D = outside with all failing; partial pass/fail events are excluded. `abcd_sideband_mode`: `complement` (default, production) or `annulus` (`abcd_sideband_width` band around each box). `abcd_mode`: `union` (default) applies one scale `B·C/D / A_union` (times `qcd_predict_scale_multipliers`) to the MC-true QCD per SR; `per_sr` (production; exactly one ABCD branch, multiplier 1) predicts `A_i = C_i × B/D` with `C_i` the box in `abcd_control_window[tree]` (exclusive, inside the fail region; production [20, 50] GeV) and B / D the pass region / control window in the sideband, and passes `abcd_per_sr_nonclosure[tree]` (required; production 0.2) to combine.
- **ROOT output** (`root_file_name`, default `qcd_abcd_yields.root`). `metadata/signal_regions` (TTree `bin_index`, written with uproot `mktree`: since uproot 5.7 dict assignment writes an RNTuple, which `combine.C` cannot read), `metadata/sr_csv_hash` (first 13 hex digits of the SHA-256 of the SR CSV, as a double). Bundles `samples/*`, `groups/<slug>`, `qcd_predict`, `qcd_true`, `total_predict`, `total_true`, each with one-bin `sr{bin_index}/{yield, stat_error, scale_error, n_entries}`, `covariance_total` (TH2) and `mean_event_weight` (the bundle's median |w| over all selected events with every ABCD branch passing; the name is kept for combine). MC-true bundles: `stat_error = sqrt(Σ w²)`, `covariance_total = diag(Σ w²)`. `qcd_predict`: union mode `stat_error` from the per-SR `A_i/A` fraction, `scale_error` the B/C/D-propagated scale uncertainty, `covariance_total` their sum (scale part fully correlated); per-SR mode `C_i^QCD × TF` with `stat_error` from `C_i` and `scale_error` from TF; `mean_event_weight` = scale × QCD median |w|. `qcd_predict/abcd_scale` (= predicted / MC-true QCD in the A union, the MC closure; 0 with a warning without QCD MC) and `abcd_scale_error`. Per-SR mode adds `qcd_predict/{per_sr_abcd (= 1), abcd_tf, abcd_tf_error, abcd_nonclosure}`, `control/{samples/*, groups/*, qcd_true}` (`sr{bin_index}` = control region of that SR) and `abcd_bd/{samples/*, groups/*, qcd_true}` (sub-bins `b`, `d`), with `mean_event_weight` in the control window.
- **Plots.** `qcd_abcd_region_counts[_linear].pdf`, `qcd_abcd_region_fractions.pdf` and their `_qcd_merged` versions (QCD classes merged), the prediction plots (per-SR mode: C and D in the control window), and optional `a_region_shapes/` per-class unit-area shapes per SR and A-union (values `<= -10` dropped). qcd_est logs raw and final scales and per-SR predictions.

`background_estimation/submit_sr_qcd_est.sbatch <category>` runs `signal_region_hist.py config_hist_<category>.json` and then `qcd_est.py` with `config_<category>.json` in one SLURM job (qcd_est only after a successful scan).

## CMS combine wrapper (`combine/combine.C`, mode 7)

Reads `COMBINE_CONFIG_PATH` (default `./config.json`); one channel per `{name, root_file, bdt_root}`; must run where `combine` and `combineCards.py` are available (fasrc: the `combine-standalone` image, CombinedLimit v11.1.0; documentation https://cms-analysis.github.io/HiggsAnalysis-CombinedLimit/latest/; a `CMSSW_*` area inside the repository is git-ignored).

- **Registry.** `class_groups` from each channel's `bdt_root/config.json` (else `fold0/config.json`), `sample_config` resolved relative to the nearest `selections/BDT` ancestor of `bdt_root` (else its parent). All channels must share the class order, the signal classes with their samples, the signal samples and the QCD classes; background classes may differ per channel (`loadRegistry` takes the union of members, logs per channel the samples its `class_groups` lack; a sample in different classes in different channels is an error). Groups are matched to `groups/*` by the slugified lowercase name. Channels may have different SR counts (`metadata/signal_regions`, else `sr1..srN`); nothing is padded. Every configured group and signal sample must exist; missing or zero-rate inputs are never regularised or synthesised.
- **Scenarios.** `combined` (signal = all signal groups), `class` (one per signal class), `sample` (one per signal sample; backgrounds = the other available sample bundles), restricted by `scenario_scopes`; each run with MC-true QCD and with the ABCD prediction (`bkg_qcd` replacing every QCD class; MC-true backgrounds are `bkg_<slug>`, the signal is `signal`). Every process carries its MC member samples (none for `bkg_qcd`).
- **Cards.** Each SR is a one-bin shape bin `<channel>_sr<bin_index>` (`shapes_<channel>.root`, Asimov `data_obs` = sum of processes, observation and rates `-1`, an exactly empty template rate `0` because combine rejects a zero-integral `-1` process with "Null norm"). Default statistical model: `* autoMCStats <mc_stat_threshold>` with template errors = `stat_error`; zero-count floors `zc_<bin>_<process> gmN 0 α` (α = `mean_event_weight`; the template holds α) for floor-eligible processes (background classes in `combined`/`class`, and `bkg_qcd` in union mode) in bins with zero yield, started at 0 via `--setParameters rgx{zc_.*}=0` (combine starts `gmN N` at N + 1); floor-carrying processes are never dropped. Union-mode ABCD: `qcd_abcd_stat_<channel>` (1 + `abcd_scale_error/abcd_scale`) and `qcd_abcd_nonclosure_<channel>` (1 + |1 − `abcd_scale`|), per channel, correlated across its SRs.
- **Per-SR ABCD** (ROOT marker `qcd_predict/per_sr_abcd` = 1): a control card `card_<channel>_abcdcr.txt` with bins `<channel>_cr<id>` (C_i), `<channel>_abcdB`, `<channel>_abcdD` built from `control/` and `abcd_bd/`, with `bkg_qcd` templates 1 in each C_i and the MC QCD in B and D, normalised by free rateParams `qcdC_<channel>_sr<id>` (absolute, start = MC QCD in C_i, range `[0, max(10 × Asimov count, 10)]`), `qcdB_<channel>`, `qcdD_<channel>` (relative, `[0, 10]`); in the SR card `bkg_qcd` holds the MC transfer factor (no floor, zero error) scaled by the formula rateParam `qcdA_<channel>_sr<id> = qcdC × qcdB / qcdD`, plus `qcd_abcd_nonclosure_<channel>` = 1 + `abcd_nonclosure`. The QCD uncertainty is thus the Poisson uncertainty of the control counts, and signal contamination of the control regions is fitted. The B and D bins carry no `lumi`, `trigger` or `xsec` (`isAbcdBdBin`): the free `qcdB`/`qcdD` absorb any change of their non-QCD MC, so these bins cannot constrain such nuisances, but in regions of up to ~1e9 events they forced narrow valleys that broke the 5-channel minimisation (2026-10-13); the transfer factor changes by only δ × (f_B − f_D) ≤ 0.5% for δ = 15%. The control card has no per-SR ratio rows.
- **lnN rows.** `kRatioNuisances` (`theory_pdf`, `theory_scale`, `theory_ps_isr`, `theory_ps_fsr` from `theory_syst_json`; `pileup`; `jes`, `jer`, `jms`, `jmr` from `{jes,jer,jms,jmr}_syst_json`): per process and SR the mean of its samples' per-SR ratios weighted by their `samples/*` yields; under theory a sample without `has_theory_weights` counts with 1; a sample with positive yield and no ratio, and a non-positive or non-finite kappa, are errors; written `κ_down/κ_up`. `theory_scale` is one nuisance per process (`theory_scale_<process>`, correlated across channels); the others are correlated across processes, SRs and channels. `lumi` (`lumi_unc`) and `trigger` (`trigger_unc`) are flat on every process with MC samples. `xsec_<process>`: per process with MC samples, κ = 1 + the yield-weighted mean of its samples' fractions from the `uncertainties` object of `xsec_unc_json` (fnmatch patterns, fractions in [0, 1); no match or conflicting matches for a sample with positive yield are errors; all-1 rows omitted), in the SR bins and the C_i bins, correlated across bins and channels. Every per-SR ratio JSON must carry the channel's `sr_csv_hash` (mismatch = error, missing hash = warning).
- **Config validation.** `enabled_nuisances` (empty = all) accepts the `kRatioNuisances` names and `lumi`, `trigger`, `xsec`, `autoMCStats`, `zero_count_floor`, `qcd_abcd_stat`, `qcd_abcd_nonclosure`; an unknown name, an enabled ratio nuisance whose JSON is unset or missing, enabled `lumi`/`trigger` with a non-positive fraction, and enabled `xsec` without `xsec_unc_json` are errors.
- **Running.** `combineCards.py` per scenario, then `combine -M Significance -t -1 --expectSignal 1 --rMin -5 --rMax 10` (`kSignificanceRRange`: with the default r ≥ 0 the significance of a valid card came out exactly 0) and `-M AsymptoticLimits -t -1 --run expected` (default r ≥ 0). CSVs: `significance.csv`, `limits.csv`, `significance_abcd_mc.csv`, `limits_abcd_mc.csv` and the per-channel `*_by_channel*.csv` (extra `channel` column). A `sample` scenario whose signal is zero in some channels skips them (in every channel: significance 0, limits `inf`); missing limit quantiles keep the significance and store `nan` limits; any other failed scenario is logged and stored as `nan`, the CSVs are still written and the run exits non-zero. Work files under `output_dir/work/<qcd_mode>_<scope>_<name>/` (single-channel: `channel_<channel>_...`), removed only with `keep_work: false`.
- **`use_root_covariance=true`:** no autoMCStats or floors, template errors 0; each process's `covariance_total` is eigen-decomposed and every eigenmode with `λ > eigen_rel_cutoff × max(diag)` becomes a shape nuisance `cov_<channel>_<process>_eig<k>`; with `rescale_shape_modes_to_positive` a mode that would make a bin or norm non-positive is scaled by the largest safe `a < 1` with datacard coefficient `1/a`, and identically zero backgrounds are dropped.

## Data/MC and sensitivity plots

`plotting/data_mc.py` (mode 4, `PLOT_CONFIG_PATH`) runs per tree a fill stage and a plot stage (`--fill-only`, `--plot-only` / `--restyle`):

Data: every entry, weight 1, `{sample_group}_mixed` rewritten to `{sample_group}`.
- Fill: one `multiprocessing` task per file; standardisation in the stored dtype; selection = `selection.json` thresholds (none with `--no-selection`) plus `plot_thresholds[tree]`; blinding (default) removes data events inside any SR box of `signal_region_csv[tree]` with all thresholds (qcd_est's A region), MC is never blinded; `--unblind` keeps them; a tree without SRs must be in `unblinded_trees`. Histograms on a fine grid of `hist_refine` × bins (ranges from `x_range`, `[0, 1]` for scores, else a scan of `range_scan_entries` entries per sample; sentinels and non-positive log-x values dropped per branch), theory members for samples with `has_theory_weights`, written to `{output_root}/{tree}_hists.npz` with metadata (SR CSV and hash, counts, flat theory fractions weighted by each sample's selected MC yield).
- Plot: rebinned histograms with overrides from `plotting/branch.json` (`bins`, `x_range`, `y_range`, `logx`, `logy`; `logy` default on), theory band from the member histograms (else the flat fractions: per sample the mode-8 acceptance ratios and the `xsec_unc_json` cross-section uncertainty in quadrature, combined over the class weighted by the selected yields), `{tree}_{branch}.pdf` and `{tree}_{branch}_normal.pdf` (unit area, `A.U.`); blinded plots carry a note. `_compare_score_reference` is defined but not called (score validation is an open item).

`plotting/class_shapes.py` (mode 10) reuses data_mc's streaming helpers (`_prepass`, `_stream_hists`) for per-class unit-area shapes with the same weights and `exclude_samples`.

`plotting/sr_sensitivity.py` (`SR_SENSITIVITY_CONFIG_PATH`, default `plotting/config_sr_sensitivity.json`; `sbatch plotting/submit_sr_sensitivity.sbatch`) imports `qcd_est.py` once per referenced config (setting its `INFERENCE_THREADS` to the allocated CPUs; no reference validation; qcd_est's `exclude_samples` are left out) and writes to `output_root`: `sr_yield_summary.pdf` (stacked `groups/*` SR yields of every `summary_categories` ROOT file with per-SR Asimov Z; all categories must share `class_groups` and `lumi`), per `targets` entry `{tree}_sr{N}/{variable}.pdf` (A-region events of that SR, N−1 for cut variables with cut lines, MC-stat band, optional scaled signal line, per-bin S/√B, per-class yields cross-checked against the ROOT file), and with `data_overlay` blinded `{variable}_data.pdf` (data outside `blind_window`, MC scaled to the data sidebands) from per-file data histograms of `python3 plotting/sr_sensitivity.py --data-file K` (array job `plotting/submit_sr_sensitivity_data.sbatch`, one histogram file per data file required). k-fold models read every MC entry through `read_sample` and score data by `data_fold`.

## Configuration Architecture

All tools are driven by JSON configs; samples live in [src/sample.json](src/sample.json), referenced through `sample_config`.

## `run.py` Behavior

[run.py](run.py) dispatches modes 0–14 (`MODES`): C++ modes 0 (`convert_branch`), 1 (`weight`), 6 (`mix`), 7 (`combine`); Python modes 2 (`train.py`), 3 (`signal_region_hist.py`), 4 (`data_mc.py`), 5 (`qcd_est.py`), 8 (`theory_syst.py`), 9 (`pileup_syst.py`), 10 (`class_shapes.py`), 11–14 (`jes/jer/jms/jmr_syst.py`). Each mode runs in its directory with `<TOOL>_CONFIG_PATH` set (default `config.json` there); the log `log.txt` (`log_<config stem>.txt` for another config) is appended to and, for local runs of modes 1, 2, 3, 4, 5, 7, copied to the output directory at exit (skipped with a warning when it does not exist). Sample arguments are accepted only for modes 0, 1, 6 (default `submit_samples`, else every MC sample). Scripts log in the `Running ...` / `Wrote ...` / `Runtime error: ...` style.

- **Local sample modes** run with `MAX_CONCURRENT_JOBS` (default 1); mode 0 as described in the convert section. Local runs build and remove the plain `{bin_name}`; `--slurm` builds `{bin_name}_{hash}` (source, `src/simple_json.h`, OpenMP, correctionlib and `root-config` flags) and reuses it, so queued jobs keep their binary.
- **`--slurm`**: mode 0 submits one job per `--slurm-files-per-job` batch (`OMP_NUM_THREADS=${SLURM_CPUS_PER_TASK}`) plus a merge job (`--dependency=afterany`) that fails if any batch is missing, incomplete or stale; modes 1/6 one job per sample (`--slurm-retries`). Mode 2 submits one job per tree (and k-fold rotation) running the site's Python command (`python_command(site, --python-env)`) with `BDT_TREES` / `BDT_FOLD` (`bdt_train_<tree>[_fold<r>]_%j.out` in `selections/BDT/`). `--slurm-cpus` / `--slurm-mem` default to 32 / 200G for mode 2 and 1 / 4G otherwise; `--slurm-time`, `--slurm-account` (site default), `--slurm-partition`, `--slurm-exclude` (default empty), `--slurm-extra`. Other Python modes run in the current process.
- **Sites** (`--site`, `SITES`): `purdue` (default; tools on the `PATH`, proxy copied from `/tmp/x509up_u<uid>` to the depot, account `cms-express`). `fasrc` (Cannon): C++ compile, `root-config`, correctionlib detection and binaries through `/cvmfs/cms.cern.ch/common/cmssw-el9 --command-to-run sites/fasrc/cmssw_exec.sh` (cmsenv in the git-ignored `CMSSW_16_1_0_pre4/`, `PYTHONNOUSERSITE=1`), mode 7 through `singularity exec --bind /n` of the CVMFS `combine-standalone:latest` image (host `LD_LIBRARY_PATH`/`PYTHONPATH`/`ROOTSYS` unset), Python through `pixi run --frozen -e <--python-env> python3` (`default` CPU, `gpu` CUDA XGBoost); fixed `-fopenmp` flags; hashed binaries always built and kept; the proxy from `--x509-proxy` or `$X509_USER_PROXY` exported as is, `X509_USER_CERT`/`X509_USER_KEY` removed (the XRootD TLS client would try the passphrase-protected key); `VVV_SCRATCH` required for `TMPDIR`, `MPLCONFIGDIR`, `XDG_CACHE_HOME`, `PIXI_CACHE_DIR`, `SINGULARITY_CACHEDIR`; account `iaifi_lab`; with `--slurm` on a login node `submit_driver_job` submits run.py itself: modes 0/1/6 and 2 keep `--slurm` in a small driver job (compile, DAS, submission from a worker), every other mode runs inside one job with the `--slurm-*` resources. Inside an allocation `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS` = `SLURM_CPUS_PER_TASK`. `ihep` (lxlogin + HTCondor, integrated 2026-10-08, kept but no longer used by the campaign): native CMSSW_16_1_0_pre4 through `sites/ihep/cmssw_exec.sh` (`HOME` moved to `build/ihep/home` when AFS is not writable), hashed binaries, `--condor` submission of the sample modes through `hep_sub` (`condor_submit`, `launch_mode0_condor`, `launch_job_condor`; scripts in `build/condor/jobs/`, logs in `build/condor/logs/`; `--condor-cpus`, `--condor-mem`, `--condor-walltime`); mode 0 submits only the batches and `--merge-only` the merges; DAS queries run on lxlogin (workers have no network, so mode 1 cannot run there). `query_batch_count` is shared by the Slurm and HTCondor paths. `convert_branch.C` and `weight.C` accept `remote_input_rules` (`[{"lfn_prefix", "url_prefix"}]`, first match wins, else `root://cms-xrd-global.cern.ch/`; `remoteInputUrl`); the `.files` snapshots and `.meta` hashes contain the resulting URLs.
- `pixi.toml` has a CPU `default` environment (`py-xgboost-cpu`) and a `gpu` environment (`py-xgboost-gpu`), both with scikit-learn, scipy and zstandard; `pixi.lock` records the resolution. The legacy `run.sh` supports modes 0–7 only and cannot build the current `convert_branch.C` (no correctionlib).

## C++ Expression Engine (convert_branch.C)

Selection and branch formulas are parsed by a mini expression engine in [selections/convert/convert_branch.C](selections/convert/convert_branch.C): arithmetic, logical and comparison operators; `pt`, `eta`, `phi`, `mass`, `abs`, `min`, `max`, `size`, `deltaR`, `deltaPhi` (signed), `min_deltaR(self, coll)`, `relPtDiff`; `pair_{min,max}_{deltaR,deltaPhi}(coll, n)` over the first `n` objects (|Δφ|); collection summaries `sum`, `max_value`, `min_value`, `nth_max_value(coll, expr, rank, default)`, `value_at_max(coll, key, value, default)`, `value_at_nth_max(coll, key, value, rank, default)`; indexing `ak8[0]`; `self` / `other` in per-object selections.

Every parsed node stores an `Op` code; `resolveEngineSymbols()` (once in `main`) resolves names to slots: event variables (input scalars, sample metadata, MC weights, scalar outputs of the tree being filled) in the flat `EventVars` array (`EventVarLayout`), collections in `EventCollections` by slot, fields by `ObjectSchema::id`. Lookup order: field of the current object, event variable (a scalar output once computed in the current tree), runtime collection already built, input collection. Unknown collection sources, merge children, `deduplicate_against` references and merge cycles are startup errors. Before the preselection `processInputFile` reads only the scalars it uses, plus `Pileup_nTrueInt` and `genWeight` for MC and `run`/`luminosityBlock` for data without a `LuminosityBlocks` tree; the full entry is read only for passing events.

## Physics Context

- **Signal:** VVV hadronic decays — WWW, WWZ, WZZ, ZZZ — and VH(→WW).
- **Trigger:** `DST_PFScouting_JetHT` scouting stream.
- **Jets:** AK8 `ScoutingFatPFJetRecluster`, AK4 `ScoutingPFJetRecluster2`.
- **Analysis trees:** `boosted3`, `boosted2_resolved`, `boosted2_unresolved`, `boosted2_leptonic_1lep`, `boosted2_leptonic_2lep`; SRs are BDT score boxes per tree.
- **QCD background:** ABCD with the SR score boxes and the `msoftdrop_1` window, in production per SR from the 20–50 GeV control window, fitted in combine.
- **Corrections and systematics:** Winter24HLT_V1 HLT JEC, offline AK4PFPuppi JER proxy, flat 10% JES, JMS/JMR from the ttbar CR, Type-1 MET, pileup (nominal/low/high); the combine nuisances are listed in README.md ("Systematic uncertainties").
