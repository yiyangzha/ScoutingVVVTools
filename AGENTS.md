Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

## 0. Guardrails

- Never overwrite user edits between reads.
- Never restore deleted code without confirmation.
- Make the smallest fix that solves the problem.
- No scope drift: no refactors, restyles, or extras unless asked.
- Fix root causes, not symptoms.
- Use web search for unstable or version-specific behavior; cite sources.
- State assumptions; ask only when blocked.
- Briefly narrate multi-step tool usage.
- Finish the full plan once started.
- If anything in the user's request is unclear, surprising, contradictory, or looks possibly wrong, stop and ask for clarification before modifying the code. Only proceed once the user has confirmed.

## 1. Non-Destructive File Handling

**Preserve user data. Prefer additive changes over destructive ones.**

- Never delete files or directories.
- Never run destructive commands or cleanup operations that remove user data.
- Do not use `rm`, `del`, `erase`, `rmdir`, `Remove-Item`, or equivalents.
- Do not remove files just because they look temporary, generated, redundant, cached, old, or replaceable.
- Do not delete files before recreating or renaming them.
- If replacement is needed, write a new file and leave the original intact.
- If renaming fails, keep the old file and create a new one with a different name.
- If deletion seems necessary, stop and propose a non-destructive alternative first.

Default rule: when in doubt, keep all existing files.

## 2. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

## 3. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

## 4. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it - don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: Every changed line should trace directly to the user's request.

## 5. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" -> "Write tests for invalid inputs, then make them pass"
- "Fix the bug" -> "Write a test that reproduces it, then make it pass"
- "Refactor X" -> "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:
```
1. [Step] -> verify: [check]
2. [Step] -> verify: [check]
3. [Step] -> verify: [check]
```

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

---

**These guidelines are working if:** fewer unnecessary changes in diffs, fewer rewrites due to overcomplication, and clarifying questions come before implementation rather than after mistakes.


# Repository Information

This file provides guidance to Claude Code (claude.ai/code) or Codex when working with code in this repository.

## Overview

This is a CMS physics analysis toolkit for a VVV (triple vector boson) scouting search using Run 3 data. The workflow processes CMS NanoAOD-style ROOT files from DAS, applies selections, can reshuffle converted sample entries into a mixed dataset for stable train/test splitting, trains BDT or PyTorch NN models, and estimates backgrounds.

**Dependencies:** ROOT (with `root-config`), C++17, Python 3, OpenMP (optional), XRootD for remote files.

## Pipeline Overview

The analysis runs in this order:

1. **Skim** — reduce raw NanoAOD files to manageable size (`legacy/skim/`)
2. **Pileup weights** — derive MC pileup reweighting CSVs (`selections/weight/`)
3. **Convert** — apply physics selections, build model training trees (`selections/convert/`)
4. **Mix** — shuffle per-sample tree entries across ROOT chunks while preserving chunk sizes (`selections/mix/`)
5. **B-veto** — derive AK4 b-jet veto working points (`selections/b_veto/`)
6. **BDT/NN training** — train `fat2`/`fat3` classifiers (`selections/BDT/`)
7. **Background estimation** — QCD ABCD validation on the MC test split (`background_estimation/`)
8. **Data/MC plotting** — compare distributions of `fat2`/`fat3` variables in data vs MC (`plotting/`)
9. **Combine** — wrap CMS `combine` to compute expected significance and `AsymptoticLimits` from the `mode=5` ROOT output (`combine/`)
10. **Systematics** — trigger efficiency studies (`systematics/`)

`systematics/find_duplicate_entries.C` is a standalone ROOT diagnostic macro that scans either one ROOT file or a directory searched recursively for `.root` files, chains the matching trees with `TChain`, and reports duplicated event keys (`run`, `luminosityBlock`, `event`) plus their multiplicities and first/last entry indices.

`systematics/plot_branch_histograms.C` is a standalone ROOT plotting macro with its input sources, TTree name, branch list, histogram ranges, binning, and log-x choices configured directly in the source. Each `INPUT_FILES` entry may be a local ROOT file, a local directory searched recursively for `.root` files, a `root://` ROOT file, a CMS `/store/...root` file that is prefixed with the global XRootD redirector, or a CMS DAS dataset path of the form `/A/B/C`; DAS dataset entries are expanded with `dasgoclient` using the CMS global XRootD redirector and filtered by the inclusive `REMOTE_DATASET_FILE_NUMBER_MIN`/`REMOTE_DATASET_FILE_NUMBER_MAX` range parsed from the trailing digits immediately before `.root` in each returned ROOT file basename. The macro processes every resolved ROOT file independently with a single-file `TChain`, auto-detects scalar versus C-array numeric branch leaves from ROOT metadata, fills variable-length NanoAOD-style C arrays with only element index 0 using the branch's associated count leaf, and writes per-input-file ROOT/PDF outputs.

## Convert_branch.C output layout (consumed downstream)

`convert_branch.C` writes per-sample ROOT files laid out as
`{output_root}/{sample_group}/{sample}.root`, where `sample_group ∈ {signal, bkg, data}` is derived from each sample's `is_MC`/`is_signal` flags. To keep single program invocations bounded, `run.sh mode=0` first asks `convert_branch.C` for the sample's batch count and then invokes it once per batch; each batch invocation reads at most `actual_thread_count * 6` input ROOT files. Each batch is first written as `{output_root}/{sample_group}_tmp/{sample}_X.root` with zero-based `X`, then finalization merges the selected temporary batch files into the normal `output_pattern`. The convert config option `resume_successful_batches` defaults to `true`; when enabled, `run.sh mode=0` requires the actual selected sample list to contain exactly one sample, and each single-batch invocation skips an existing `{sample}_X.root` only after the matching `.raw_entries` sidecar is readable and the ROOT output opens with every configured output tree present. Existing valid batch outputs are not overwritten in that mode and are passed into the final merge together with newly completed batches. A direct `convert_branch <sample> <X>` invocation processes only batch `X` unless the resume check skips a valid existing batch; a direct invocation without a batch index keeps the compatibility path that processes all batches in one process. When the combined estimated final output exceeds `max_output_file_size_gb`, the final writer splits per-tree entries evenly across N chunks (sized so each chunk stays below the limit with ~10% margin) and writes them as `{sample}_0.root`, `{sample}_1.root`, …; when the estimate is within the limit a single `{sample}.root` is written instead. Each output chunk is built by opening a `TChain` over all relevant temporary ROOT files, cloning the output tree from that `TChain` itself so ROOT keeps branch addresses synced across temp-file boundaries, and streaming the chunk's entry range into that clone. The writer validates the planned entry count for every non-empty tree chunk before closing the file. Basket size is fixed at 32 KB and auto-flush/auto-save are disabled on the output trees so ROOT's `OptimizeBaskets` cannot inflate a basket past its 1 GB `TBufferFile` serialization limit on highly-compressible branches. Every ROOT file contains the `fat2` and `fat3` trees described by `selections/convert/branch.json`. Convert resolves configured output paths, pileup paths, and branch/selection config paths to absolute paths at startup so ROOT file I/O is less sensitive to a stale current working directory during long AFS/NFS jobs. Remote ROOT input open failures are retried five times before the batch fails and `run.sh mode=0` continues to the next batch.

For `run.sh mode=0`, batch invocations set `CONVERT_DEFER_FINAL_MERGE=1`, so every batch process only writes its temporary batch output and the script runs one explicit finalization step after the batch loop. A non-zero exit from one batch logs a warning but does not stop later batches for the same sample. The script passes the zero-based list of batches that succeeded in the current run through `CONVERT_SUCCESSFUL_BATCHES`; `convert_branch <sample> --merge-successful-batches` then merges only those successful batch outputs and writes `raw_entries` from their accumulated totals without reprocessing input files. Direct manual invocations without `CONVERT_SUCCESSFUL_BATCHES` keep the compatibility behavior of considering the existing temporary batch files.

When a per-input-file conversion exception occurs inside a batch, `convert_branch.C` reports the failing input ROOT file path in the propagated `Runtime error` message so schema or branch mismatches can be traced back to the source file rather than the batch output file.

Input ROOT files whose configured `tree_name` exists but has zero entries are skipped before branch-status configuration and branch binding; they contribute zero to the accumulated `raw_entries` count.

The convert config field `lumi_mask` may name a CMS golden-JSON-style lumi mask file relative to the convert config; when set, `convert_branch.C` applies it only to data samples before event preselection, accepts only entries whose `run` and `luminosityBlock` fall inside the mask, and counts only those accepted data entries in `raw_entries`.

Downstream scripts — `selections/BDT/train.py`, `selections/BDT/signal_region/signal_region.py`, and `plotting/data_mc.py` — all consume these files via their config's `input_root` + `input_pattern` (`{input_root}/{sample_group}/{sample}.root`). They discover every file for a given sample by globbing the base pattern **and** the `{sample}_*.root` split variant, then concatenate their trees in sorted order. The convert expression engine supports collection summaries such as `sum`, `max_value`, `min_value`, `nth_max_value(collection, expr, rank, default)`, `value_at_max(collection, key_expr, value_expr, default)`, and `value_at_nth_max(collection, key_expr, value_expr, rank, default)`. `selections/convert/branch.json` writes per-AK8 `WvsQCD` and `VvsQCD` scores, plus event-level AK8 score summaries `ScoutingFatPFJetRecluster_{WvsQCD,VvsQCD}_{sum,max}` for both `fat2` and `fat3`; `VvsQCD` uses `ScoutingFatPFJetRecluster_scoutGlobalParT_prob_Xud + Xcs + Xqq + Xbb + Xcc + Xss` over that sum plus `QCD`. It also writes AK4 b-tag summary outputs for both trees: `ScoutingPFJetRecluster2_scoutUParT_probb_max`, `ScoutingPFJetRecluster2_scoutUParT_probb_max_pt`, `ScoutingPFJetRecluster2_scoutUParT_probb_sum`, `ScoutingPFJetRecluster2_scoutUParT_probb_second_max`, and `ScoutingPFJetRecluster2_scoutUParT_probb_second_max_pt`. The model training branch list is independent and does not automatically consume newly produced convert branches.

`selections/mix/mix.C` can read that same layout and write a shuffled mirror under the same dataset root using `{sample_group}_mixed` directories (for example `dataset/signal_mixed/` and `dataset/bkg_mixed/`). For each selected MC sample and requested tree, it first scans every input chunk's tree entries once (warming ROOT serially, then using OpenMP across remaining files when available), then concatenates the chunk files through a `TChain`, applies a deterministic per-tree block shuffle seeded by `random_state` (with a random cyclic rotation inside each block), and writes the entries back into output files that preserve the original chunk filenames and per-chunk entry counts. Each non-empty output chunk is cloned from the `TChain` itself so ROOT keeps branch addresses synced as the chain advances across input-file boundaries, and the writer validates both per-chunk and total written entry counts. The block size is chosen as `clamp(total_entries / 512, min_block_entries, max_block_entries)` with defaults `32` and `4096`. The checked-in model-training config reads this mixed layout via `input_root="../../dataset"` and `input_pattern="{input_root}/{sample_group}_mixed/{sample}.root"`.

# compile

### BDT/NN training

Model outputs are written under the per-tree `output_root` configured in `selections/BDT/config.json` (for example `selections/BDT/fat2/`). The checked-in config currently points `input_root` to `../../dataset` and `input_pattern` to `{input_root}/{sample_group}_mixed/{sample}.root`, i.e. the shuffled mirror produced by `selections/mix/mix.C` under the same dataset root. The top-level `model_type` selects the trainer: `bdt` keeps the existing XGBoost workflow, while `nn` uses a PyTorch MLP and the matching per-tree `{tree}_nn` hyperparameter block (`fat2_nn` or `fat3_nn`). PyTorch is required only for `model_type: "nn"`; BDT mode does not import it. In BDT mode, `train.py` runs in two stages when decorrelation is enabled: stage 1 trains a native `multi:softprob` model with the tree's `n_estimators`, `learning_rate`, and `early_stopping_rounds`; stage 2 resumes from the stage-1 best model for `n_estimators_decorr` additional rounds at `learning_rate_decorr` and adds the configured decorrelation loss. In NN mode, stage 1 optimizes a single PyTorch-style `objective_loss = weighted_CE` with the same train/test split, training-threshold filtering, preprocessing, and event weights; when smooth-CvM decorrelation is enabled, stage 2 continues from the stage-1 best MLP and optimizes `objective_loss = weighted_CE + scaled_decorrelation_loss` using class-balanced mini-batch PyTorch gradients with sampling-corrected event weights. If a per-tree `decorrelate` branch also appears in `selection.json` thresholds, that branch's threshold is normally omitted only from the training/early-stopping objective splits and their class balancing; for decorrelate branches named `ScoutingFatPFJetRecluster_msoftdrop_*`, the training view instead applies a loose `(0, decor_msoftdrop_training_max)` window when that branch has a selection threshold. The full threshold set is still used for ordinary evaluation plots and downstream validation references. When `lr_reduce_patience > 0` and `min_learning_rate > 0`, both model types and both stages use the same dynamic learning-rate schedule: stale validation rounds halve the learning rate down to the floor, and ordinary early stopping is only active after the floor is reached. BDT stage-1/final models are saved as `{tree}_model_stage1.json` and `{tree}_model.json`; NN stage-1/final models are saved as `{tree}_model_stage1.pt` and `{tree}_model.pt`. Downstream scripts choose `.json`/`.pkl` or `.pt` from the copied `config.json` `model_type`. Each tree output directory also stores copies of `config.json`, `branch.json`, `selection.json`, the fixed per-sample test split definition `test_ranges.json`, and the saved test-set prediction references `test_reference_signal_region.npz`, `test_reference_qcd_est.npz`, and `test_reference_qcd_est_full.npz`.

Before training starts, `train.py` also writes a `branches/` subdirectory under the tree output directory containing one PDF per training branch with normalized per-class distributions overlaid (train+test events combined, values after the full evaluation threshold filtering and clip ranges but **before** the log transform); these plots are intended as a data-leakage / input-sanity diagnostic and use step histograms colored by class with legend.

`train.py` is intentionally memory-conscious during BDT/NN preparation: arrays kept after a pandas `DataFrame` is discarded should be detached copies, the unfiltered test split is kept by reference only until prediction reference files are written, branch-distribution clipping is done one column at a time, and large temporary prediction/reference arrays are released before result plotting. Preserve these no-behavior-change memory patterns when editing the training workflow.

Model-dependent comparison plots are saved twice with `_cls` / `_decorr` suffixes where applicable: `importance_cls.pdf` / `importance_decorr.pdf`, `roc_*_cls.pdf` / `roc_*_decorr.pdf`, `score_*_cls.pdf` / `score_*_decorr.pdf`, `decor_corr_{train,test}_cls.pdf` / `decor_corr_{train,test}_decorr.pdf`, `decor_score_vs_branch_cls.pdf` / `decor_score_vs_branch_decorr.pdf`, and `decor_branch_shapes_by_signal_score_cls.pdf` / `decor_branch_shapes_by_signal_score_decorr.pdf`. BDT importance uses XGBoost gain; NN importance keeps the same PDF names but uses deterministic permutation importance on the configured number of test events. Ordinary importance, ROC, score-distribution, `feature_corr.pdf`, and branch-distribution plots use the full evaluation threshold set. The two decorrelation diagnostics are multipage PDFs built from test events in the training-threshold view: score-vs-branch pages use the matching class's test sample with a black weighted-average score curve over fine branch-value bins, while signal-score-shape pages compare normalized decorrelate-branch distributions after weighted-efficiency cuts from each tree's `decor_efficiencies`. These decorrelation diagnostics keep decorrelate branch values after the training-view thresholds (including the loose msoftdrop window when applicable) and clipping but before log transform, and deliberately do not reapply the original decorrelate branch selection threshold itself. Normalized plots use `A.U.` on the y-axis. BDT `loss_mlogloss.pdf` / `loss_classification.pdf` / `loss_total.pdf` or NN `loss_weighted_ce.pdf` / `loss_objective.pdf`, plus `loss_decorrelation.pdf`, are saved once, and the loss plots draw a vertical line at the stage boundary with NN x-axes labelled by epoch and BDT x-axes by boosting round. During training, BDT stage 1 prints train/test `mlogloss`; NN prints `train_objective_loss` and `test_objective_loss`, with component `weighted_ce_loss` in stage 1 and component `weighted_ce_loss` plus `decorrelation_loss` in stage 2; BDT stage 2 keeps the legacy `mlogloss`, `classification_loss`, `decorrelation_loss`, and `total_loss` fields. In BDT mode, `classification_loss` is the sum-scale weighted softprob cross-entropy (`Σ w·(-log p_true)`), `mlogloss` is the weighted average of that same quantity (`Σ w·(-log p_true) / Σ w`), and `total_loss = classification_loss + decorrelation_loss`; BDT mode additionally reconstructs `regularization_loss` per newly added tree using that tree's current `eta` together with `gamma` / `reg_lambda` / `reg_alpha`. In NN mode, `backward()` uses class-balanced mini-batches with sampling-corrected event weights, while `train_objective_loss` and `test_objective_loss` are recomputed at epoch end in eval mode on the training-threshold train/test splits with the same batch objective formula; optimizer `weight_decay` remains native AdamW decoupled weight decay rather than a separate logged loss term. The NN stage-1 objective is weighted CE, and the NN stage-2 objective is weighted CE plus scaled smooth-CvM decorrelation. The decorrelation loss itself uses the current event weights in smooth-CvM mode for NN and in smooth/hard CvM modes for BDT. Smooth-CvM state is prepared per class so zero-weight off-class entries are not recomputed every round, and metric-only loss evaluation skips gradient/Hessian work while keeping the same recorded loss. BDT stage 1 chooses early stopping / best round on test `classification_loss`; NN stage 1 and stage 2 both choose early stopping / best epoch on test `objective_loss`; BDT stage 2 uses test `total_loss`. The fixed decorrelation scale is calibrated once from the saved stage-1 best model as `(cls_loss_stage1 + reg_loss_stage1) / max(raw_decor_loss_stage1, ε)` for BDT and batch-averaged weighted CE `cls_loss_stage1 / max(raw_decor_loss_stage1, ε)` for NN, with NN using the same mini-batch smooth-CvM raw loss used during training and epoch-end train/test evaluation. The saved reference files keep the pre-lumi physics test weights (`σ × N_tree / N_raw` with the same per-event raw-w shaping as the downstream scripts), and downstream comparison multiplies those stored weights by the local analysis `lumi` before checking them against the reconstructed physical weights.

### Signal region optimisation
```bash
# Edit selections/signal_region/config.json, then:
python3 selections/signal_region/signal_region.py
# Or with a custom scan config:
SCAN_CONFIG_PATH=/path/to/config.json python3 selections/signal_region/signal_region.py
```

`signal_region.py` reads all parameters from [selections/signal_region/config.json](selections/signal_region/config.json). It loads the saved model, branch, and selection configs from the `bdt_root` directory written by `train.py`, reloads the exact test split defined in `test_ranges.json`, applies physics-normalised weights (`lumi × σ × N_tree / N_raw`), and when `validate_bdt_test_scores=true` converts the stored reference weights to the same scale by multiplying them with the local `lumi` and validates that its reconstructed test-split prediction matches `test_reference_signal_region.npz` within the stored tolerances. It then builds `N = n_signal_regions` non-overlapping general high-dimensional rectangles in the configured model score axes (`score_axes`, defaulting to the independent first `NUM_CLASSES − 1` axes; the checked-in config uses all class-score axes). It first builds one shared candidate pool using dense per-axis boundaries from total/signal/background weighted quantiles plus tail-heavy quantiles, deterministic beam coordinate search, compatibility expansion, and optional nearby real event-threshold refinement. Local refinement can choose seeds by distinct event masks so it does not spend all refinement passes on many geometric variants of the same selected events. Candidates are filtered by weighted signal/background minima, optional event-count minima, and geometric validity, but are not trimmed by single-region Z or by a fixed global candidate cap. Before global selection, every candidate is shrunk to its event-preserving minimal score box, and duplicate removal only merges candidates that have the same exact event mask and the same rounded canonical shrunk box. The final selection is global rather than sequential: it chooses K mutually non-overlapping candidates that maximize the existing combined objective `sqrt(sum Z_i^2)`, using exact half-open `[low, high)` geometry checks matching the event-mask membership so selected SRs cannot share events. With `max_threads > 1` and a working OpenMP compiler/libomp setup, [openmp_region_select.cpp](selections/signal_region/openmp_region_select.cpp) uses a beam incumbent followed by branch-and-bound over the candidate list; if the configured time/node limits stop the search before exhaustion, the script reports the best found Z and a conservative upper-bound certificate. With `max_threads == 1` or if the helper cannot build, it falls back to the Python branch-and-bound implementation. After the K non-overlapping SRs are selected, an additional empty-bin expansion step is applied in order (SR1, SR2, …): each SR's signal-class score axes have their upper bound pushed toward `1.0` and its background-class score axes have their lower bound pushed toward `0.0`, but only into MC-empty space and only as far as the expanded box remains geometrically non-overlapping with every other selected SR. The expansion is constrained to keep each SR's exact selected event mask, so per-bin `S`/`B`/`Z` are unchanged; only the empty-side bounds in the per-SR report and in `signal_region.csv` are widened. Plots are saved as `sr_score_*.pdf`, `scores_no_regions.pdf`, `scores.pdf`, `scores_no_regions_radial_equalized.pdf`, and `scores_radial_equalized.pdf` in the configured `output_dir` (defaulting to `bdt_root` for backward compatibility). The 2D region views project the full multiclass probability vector onto the vertices of a regular `NUM_CLASSES`-gon and use a shared fixed class palette with generated extra colors if needed; the no-region version shows class-colored transparent test points and class-labeled vertices, while the region version overlays projected high-dimensional SR polygons instead of rectangles. The two `*_radial_equalized.pdf` views keep polygon vertices fixed but radially expand point positions for a more even visual fill, and all 2D views hide coordinate axes, ticks, frames, and grid lines. The selected high-dimensional region definitions are written to `signal_region.csv` in the same directory.

### QCD ABCD estimation
```bash
python3 background_estimation/qcd_est.py
# Or with a custom config:
QCD_EST_CONFIG_PATH=/path/to/config.json python3 background_estimation/qcd_est.py
```

`background_estimation/qcd_est.py` reads [background_estimation/config.json](background_estimation/config.json), then reuses the trained `bdt_root` output in the same way as `signal_region.py`: it loads the saved `config.json`, `model`, `branch.json`, `selection.json`, and `test_ranges.json`, reads the full test split with the same per-event weight definition (loading `model_branches ∪ thresholds.keys() ∪ decorrelate ∪ a_region_shape_branches[tree_name]` from each ROOT file so every branch needed for filtering, ABCD pass/fail masks, decorrelation, and optional A-region shape diagnostics is available even when it is not in `branch.json`), removes only the configured `abcd_branches[tree_name]` thresholds before model inference, applies the same clip/log preprocessing, and uses the `signal_region.csv` produced by `signal_region.py` as the set of A-region score bins. When `validate_bdt_test_scores=true`, it converts the stored reference weights to the local physical scale by multiplying them with the configured `lumi` and validates against `test_reference_qcd_est_full.npz` when present (falling back to the legacy filtered `test_reference_qcd_est.npz`). BDT inference in qcd_est is intentionally batched, sets the loaded XGBoost Booster's `nthread` to the same capped CPU-thread convention used during training, prefers XGBoost `inplace_predict` with a batched `DMatrix` fallback, and reuses the full-test probabilities for the non-ABCD-filtered event view when the full reference-validation path is active; otherwise it predicts after the non-ABCD filtering step. The SR score axes are detected from the CSV `{axis}_low` / `{axis}_high` columns so qcd_est can consume either the legacy first `NUM_CLASSES − 1` axes or all class-score axes. It defines `A` as the union of those score bins with all configured ABCD branches passing their `selection.json` thresholds, `B` as outside that union with all configured ABCD branches passing, `C` as inside that union with all configured ABCD branches failing, and `D` as outside that union with all configured ABCD branches failing; events where only some configured ABCD branches pass are excluded from A/B/C/D. QCD classes are identified by `class_groups` names containing `qcd` case-insensitively, and all samples from those classes are summed for the ABCD `A/B/C/D` totals, `qcd_true`, `qcd_predict`, and `total_predict`; the per-class `groups/*` outputs remain the MC-true class yields. A single QCD ABCD scale from the union-level `B/C/D` totals is then applied to all individual signal regions, after the optional per-tree `qcd_predict_scale_multipliers` factor is applied; qcd_est logs the raw ABCD prediction, raw scale, manual multiplier, final scale, and per-SR raw/scaled QCD predictions for debugging. The validation plots keep the finite-MC / ABCD-propagated uncertainties based on `sum(w^2)` and the B/C/D propagation; `qcd_abcd_region_counts.pdf` and `qcd_abcd_region_fractions.pdf` stack the configured `class_groups` classes with the shared fixed class palette and generated extra colors if needed, while `qcd_abcd_region_counts_linear.pdf` saves the same counts with a linear y axis. The QCD-merged summaries (`qcd_abcd_region_counts_qcd_merged.pdf`, `qcd_abcd_region_counts_qcd_merged_linear.pdf`, and `qcd_abcd_region_fractions_qcd_merged.pdf`) combine every `class_groups` class whose name contains `qcd` case-insensitively into one `QCD` stack color and legend entry, leaving non-QCD classes unchanged. Optional per-tree `a_region_shape_branches` entries produce normalized branch-shape PDFs under `output_dir/a_region_shapes/`; for each configured branch, qcd_est writes one class-overlaid, unit-area weighted histogram for every signal bin plus one for the full A-union, without applying ABCD prediction scaling, and drops values `<= -10` before binning/normalization so missing-slot values such as `-99` do not set the visible range. The ROOT output is combine-facing: it writes `metadata/signal_regions` with the selected `bin_index` values, and every saved category (`samples/*`, `groups/*`, `qcd_predict`, `qcd_true`, `total_predict`, and `total_true`) stores each SR as one-bin histograms under `sr{bin_index}/yield`, `sr{bin_index}/stat_error`, and `sr{bin_index}/scale_error`, plus a category-level `covariance_total` TH2. The combine-facing convention is `stat_error = sqrt(yield)`, `scale_error = 0`, and diagonal `covariance_total = diag(yield)`, treating each weighted yield as the Poisson event count.

### CMS combine wrapper
```bash
./run.sh 7
./run.sh 7 combine/config.json
```

`combine/combine.C` wraps CMS `combine` to compute expected significance and expected `AsymptoticLimits` (CLs) from the ROOT output of `qcd_est.py`. It reads [combine/config.json](combine/config.json), which lists one or more channels, each pointing to a `qcd_abcd_yields.root` written by `mode=5` and the matching per-channel `bdt_root` directory written by `train.py`. `combine.C` loads `class_groups` from each channel's `bdt_root/config.json`, resolves that copied config's `sample_config` the same way as `qcd_est.py`, and requires all channel BDT configs to share the same class membership plus signal/QCD definitions before building one shared scenario list. Group names from `class_groups` are matched against `groups/*` in the ROOT file by the same slugified lowercase convention used by `qcd_est.py`, and QCD classes are the class names containing `qcd` case-insensitively. It must be run inside a CMSSW area that has `HiggsAnalysis/CombinedLimit` built, so that `combine` and `combineCards.py` are on `$PATH`.

For every channel it loads the stored yield/covariance bundles from that channel's own SR list (`metadata/signal_regions` when present, otherwise sequential `sr1..srN` for older files): `samples/{sample}/srN/{yield,stat_error,scale_error}`, `groups/{group}/srN/{yield,stat_error,scale_error}`, `qcd_predict/srN/{yield,stat_error,scale_error}`, and each bundle's `covariance_total`. Different channels, such as `fat2` and `fat3`, may have different SR counts; no channel is padded or truncated. It then iterates over scenarios:
- `combined`: signal = the sum of all signal groups from `groups/`; backgrounds = the remaining groups.
- `class`: one row per signal class; signal = that class's `groups/` block; backgrounds = every other group.
- `sample`: one row per signal sample; signal = that sample's `samples/` block; backgrounds = the remaining available sample blocks.

For each scenario combine is run twice: once using the MC-true group/sample yields directly from the ROOT file, once replacing all QCD classes (matched by `class_groups` names containing `qcd` case-insensitively) with the single merged `qcd_predict` yield while keeping the other backgrounds on their MC-true group/sample yields. Every channel is validated before running: all configured groups must exist, every configured signal sample must exist, and the code refuses to regularize, clamp, or synthesize missing/zero-rate inputs. By default `use_root_covariance=false`, so each SR is written as its own pure counting bin named `<channel>_sr<bin_index>`; stored `covariance_total` blocks are validated and kept in the ROOT file but are not encoded as Gaussian shape nuisances. Combine's binned Poisson likelihood supplies the counting statistics from the weighted yields, matching the `signal_region.csv` Asimov significance convention, avoiding double-counting those same statistical fluctuations, and avoiding the old multi-bin shape-PDF factorization warning. If a `sample` scenario's signal process is identically zero in some channels, those channels are skipped with a warning; if the signal sample is identically zero in every channel, the wrapper logs a warning, writes `0` into the significance CSV field and `inf` into the limit CSV fields, and continues with the remaining scenarios. If `AsymptoticLimits` returns successfully but its ROOT output still lacks the expected quantiles, the wrapper logs a warning, writes `0` into the corresponding significance CSV field and `inf` into the limit CSV fields, and continues with the remaining scenarios.

When `use_root_covariance=true`, each process's `covariance_total` is additionally eigen-decomposed and every retained eigenmode (eigenvalue `> eigen_rel_cutoff × max(diag(cov))`) becomes one Gaussian shape nuisance. The templates start from `Up_i = rate_i + √λ_k · V_{i,k}` and `Down_i = rate_i − √λ_k · V_{i,k}`; if that would make any bin or whole-template norm non-positive and `rescale_shape_modes_to_positive=true`, the wrapper instead writes `Up_i = rate_i + a·√λ_k · V_{i,k}` and `Down_i = rate_i − a·√λ_k · V_{i,k}` with the largest safe `a < 1`, then compensates in the datacard with a `shape` coefficient of `1/a`. This optional mode represents extra process-yield covariance beyond the native Poisson counting statistics and writes one-bin shape templates for each SR. Per-channel datacards and optional covariance shape ROOT files are written under `output_dir/work/<qcd_mode>_<scope>_<name>/` for the all-channel run and under `output_dir/work/channel_<channel>_<qcd_mode>_<scope>_<name>/` for single-channel reruns. `combine` is then invoked as `-M Significance -t -1 --expectSignal 1` and `-M AsymptoticLimits -t -1 --run expected`, and the resulting `higgsCombine*.root` files are parsed to fill four all-channel CSVs in `output_dir`: `significance.csv`, `limits.csv`, `significance_abcd_mc.csv`, and `limits_abcd_mc.csv`. It also reruns the same scenarios for each configured channel individually and writes `significance_by_channel.csv`, `limits_by_channel.csv`, `significance_by_channel_abcd_mc.csv`, and `limits_by_channel_abcd_mc.csv` with an extra `channel` column. The MC-true and ABCD CSVs share the same row order within their all-channel and per-channel groups. When `keep_work: true` (default) the generated datacards, optional shape ROOT files, and combine outputs are left in place for inspection; with `keep_work: false` the work directory is removed after the final CSV is written.

`plotting/data_mc.py` reads [plotting/config.json](plotting/config.json) and [plotting/branch.json](plotting/branch.json), then for every tree in `submit_trees`:
- Loads the BDT-tree copies of `config.json` (to get `class_groups`, `input_root`, `input_pattern`), `branch.json` (to get model input branches), and `selection.json` (for `clip_ranges`, `thresholds`, `log_transform`) from the directory resolved by `bdt_root` with `{tree_name}` substituted. It reads `test_ranges.json` only when `plot_bdt_scores=true`. `input_root` is resolved relative to the BDT script directory (the parent of `bdt_root`), matching `train.py`'s convention.
- Discovers plottable ordinary variables from `selections/convert/branch.json`'s output entries for the tree (only `onlyMC: false`, expanding `slots` into `{name}_1` … `{name}_N`, minus that tree's `skip_branches` from `plotting/branch.json`) and does not restrict those ordinary ROOT branches to the BDT input list. When `plot_bdt_scores=true`, it appends one derived model score branch per class named `score_{class_name}` unless skipped.
- For each MC sample listed in any active `class_groups` entry, it globs the convert_branch ROOT files (`{sample}.root` + `{sample}_*.root`), sums the tree entries across all of those files, then loads all entries for ordinary ROOT-branch plots together with the tree's `event_reweight_branches` from `plotting/config.json` (default `{"fat2": ["weight_pu"], "fat3": ["weight_pu"]}`). It computes `raw_w` as the product of those reweight branches on raw values (before any clip/log/threshold) and then drops them, and assigns per-event weight `raw_w × target_total / Σ raw_w_loaded` with `target_total = lumi_total × xsection × tree_entries_total / raw_entries`. Missing MC files, empty MC trees, empty MC classes before filtering, non-positive `raw_entries`, or non-positive `Σ raw_w_loaded` raise `RuntimeError`. `lumi_total` is the sum of `lumi` fields in `src/sample.json` for every sample name in `data_samples` (every listed data sample **must** already exist in `src/sample.json` with `is_MC: false`, otherwise data_mc.py errors out). Missing reweight branches in a read MC file raise `KeyError`. The per-event weight is frozen before any cuts and is not recomputed later.
- For each data sample in `data_samples`, loads every event with `weight = 1` per event. Data samples do not read the reweight branches. Data uses the copied BDT `input_pattern` with `{sample_group}_mixed` rewritten to `{sample_group}`, so the checked-in mixed MC pattern resolves data to `dataset/data/` rather than `dataset/data_mixed/`; missing sample files are treated as fatal errors rather than falling back to another directory.
- Applies threshold cuts, then clip ranges, both from the BDT tree's `selection.json`. `log_transform` is **not** applied — it only influences the default `logx` flag for plotting.
- For derived score branches only, MC is loaded from the saved test split in `test_ranges.json`, weighted per sample to the same full-sample target total `lumi_total × xsection × tree_entries_total / raw_entries` using the raw-weight sum over the loaded test split, filtered with the full BDT `thresholds`, standardised with clip/log transforms, predicted with the saved model, and, when `validate_bdt_test_scores=true`, validated against `test_reference_signal_region.npz` after multiplying the reference weights by `lumi_total`. Data score branches are predicted from the full configured `data_samples` input with unit data weights.
- Histograms each branch with the resolved binning: default `default_bins` bins, auto range from the union of MC + data, `logy` always on by default, `logx` on if the branch appears in `log_transform`; derived `score_*` branches default to `x_range = [0, 1]` and `logx = false`. `logx` uses log-spaced bins and drops non-positive values; sentinel values (`< -990`) are excluded per-branch from that branch's histogram but the event stays in the sample for other branches. Per-branch overrides from `plotting/branch.json` (`bins`, `x_range`, `y_range`, `logx`, `logy`) take precedence for ROOT branches and score branches.
- Emits stage-by-stage progress messages in the same concise style as `signal_region.py`, including config resolution, sample loading, filtering, per-branch plotting progress, `Wrote ...`, and `Runtime error: ...`.
- Saves one physical-normalization PDF per branch to `{output_root}/{tree_name}_{branch}.pdf` with a top panel (stacked MC + Data points + hatched MC uncertainty band) and a bottom Data/MC ratio panel where the propagated MC uncertainty is drawn as a shaded band around 1 and the data uncertainty remains on the points. It also saves `{output_root}/{tree_name}_{branch}_normal.pdf`, built from the same binned histograms after scaling the total stacked MC integral to 1 and the data integral to 1; the normalized plot uses `A.U.` on the y-axis, keeps the same binning/styling/stack composition, and when using automatic log-y limits lowers the y-axis minimum enough for the smallest non-empty MC stack component peak to remain visible.

## Configuration Architecture

All tools are driven by JSON config files. Sample definitions live centrally in [src/sample.json](src/sample.json); individual tool configs reference it via the `sample_config` key.

- **[src/sample.json](src/sample.json)** — master sample registry. Each entry has `name`, `path` (DAS path, string or list), `sample_ID`, `is_MC`, `is_signal`, `xsection`, `lumi`, and `raw_entries`. `convert_branch.C` updates `raw_entries` for the running sample once after the final input batch, using the chosen `tree_name` entry total accumulated across all ROOT files resolved from that sample's configured `path` values.
- **[selections/convert/config.json](selections/convert/config.json)** — controls convert step: output paths, thread count, file size limits, pileup weight CSV path pattern.
- **[selections/mix/config.json](selections/mix/config.json)** — controls the optional mix step: selected trees, input/output ROOT roots and patterns, sample config, thread count (used for the OpenMP input-chunk scan), deterministic `random_state`, and the block-size bounds `min_block_entries` / `max_block_entries` (defaults `32` / `4096`) used for per-tree block shuffling while preserving chunk layout.
- **[selections/convert/selection.json](selections/convert/selection.json)** — physics selection: event preselection string, per-collection cuts/sorts, and `tree_selection` that splits output into `fat2` (exactly 2 AK8 jets) and `fat3` (≥3 AK8 jets) trees. Selections are parsed and JIT-compiled by the C++ expression engine.
- **[selections/convert/branch.json](selections/convert/branch.json)** — declares all input NanoAOD branches to read (scalars and collections with p4 definitions) and output branches to write.
- **[selections/weight/config.json](selections/weight/config.json)** — pileup reweighting settings: data pileup histogram files (nominal/low/high for systematics).
- **[selections/BDT/config.json](selections/BDT/config.json)** — controls model training inputs and outputs: `submit_trees`, `input_root`, `input_pattern`, `class_groups`, `output_root`, `model_pattern`, top-level `model_type` (`bdt` or `nn`, defaulting to `bdt`), `entries_per_sample`, `train_fraction`, top-level `decor_loss_mode` (`smooth_cvm` by default, or legacy `cvm` for BDT), `decor_lambda`, `decor_n_bins`, `decor_n_thresholds`, `decor_score_tau`, `decor_bin_tau_scale`, `decor_msoftdrop_training_max` (positive upper edge for the loose `(0, max)` training window used only when a decorrelate branch named `ScoutingFatPFJetRecluster_msoftdrop_*` also has a `selection.json` threshold), and per-tree BDT hyperparameters (`n_estimators`, `n_estimators_decorr`, `max_depth`, `learning_rate`, `learning_rate_decorr`, optional `min_learning_rate` / `lr_reduce_patience`, `gamma`, `reg_lambda`, `reg_alpha`, `min_child_weight`, `subsample`, `colsample_bytree`, optional `colsample_bynode`, `early_stopping_rounds` with default 10) plus `decorrelate`, `decor_efficiencies` (fractions in `(0, 1]` for the decorrelation shape diagnostics), `event_reweight_branches` (list of per-event reweight branches multiplied together before sample normalisation; default `["weight_pu"]`), and `qcd_ht_training_weight_step` (per-tree additive QCD HT training-weight step; `0.10` gives scales `1.0`, `1.1`, `1.2`, ... in increasing configured QCD HT sample order and affects only `train.py`'s internal training/evaluation weights, not saved physics reference weights). In NN mode, `{tree}_nn` blocks (`fat2_nn`, `fat3_nn`) provide PyTorch MLP hyperparameters: `epochs`, `epochs_decorr`, `hidden_layers`, `activation`, `dropout`, `batch_norm`, `batch_size` (total events per class-balanced mini-batch), `learning_rate`, `learning_rate_decorr`, optional `min_learning_rate` / `lr_reduce_patience`, `weight_decay`, `early_stopping_rounds`, and `permutation_importance_events`; the checked-in NN blocks use `learning_rate: 0.001`, `learning_rate_decorr: 0.0005`, `min_learning_rate: 0.00002`, and `batch_norm: false` so weighted-event training is not coupled to unweighted BatchNorm running statistics.
- **[selections/signal_region/config.json](selections/signal_region/config.json)** — controls signal_region.py: `lumi` (fb⁻¹), `N` / `n_signal_regions` (number of signal regions), `bdt_root` (trained tree output directory to read from, relative to `signal_region/`), `output_dir` (directory for saved PDFs and `signal_region.csv`, relative to `signal_region/`, defaulting to `bdt_root`), `score_axes` (`independent` / first `NUM_CLASSES − 1`, `all`, or an explicit list of class names/indices), `validate_bdt_test_scores` (default `true`; compare reconstructed test scores/weights to the saved BDT reference), `min_bkg_weight` / `min_signal_weight` (minimum weighted yields per region), optional `min_signal_entries` / `min_bkg_entries` event-count minima, `max_edge_candidates_per_axis` (maximum distinct edges per score axis, including `0.0` and `1.0`), candidate-generation controls `beam_width`, `top_intervals_per_axis`, `coordinate_rounds`, `seed_intervals_per_axis`, `multi_axis_seed_max_axes`, `multi_axis_seed_max_seeds`, `compatibility_seed_anchors`, `compatibility_seed_rounds`, `local_refine_rounds`, `local_refine_neighbor_edges`, `local_refine_top_candidates`, `local_refine_diverse_masks`, and `local_refine_candidate_overscan` (`0` scans the full pre-refinement pool), global-selection controls `global_beam_width`, `branch_bound_max_nodes` (`0` for no node cap), `branch_bound_time_limit_seconds` (`0` for no time cap), `deduplicate_event_masks`, `require_exact_n_regions`, `max_threads`, `progress_every_seconds`, and `seed_quantiles`. There is no candidate-pool or global-candidate count limit in the checked-in scan path.
- **[background_estimation/config.json](background_estimation/config.json)** — controls qcd_est.py: `lumi` (fb⁻¹), `bdt_root` (trained tree output directory to read from), `signal_region_csv` (path to the `signal_region.csv` written by `signal_region.py`), `output_dir` (directory for PDFs and ROOT outputs), `root_file_name` (summary ROOT filename), `validate_bdt_test_scores` (default `true`; compare reconstructed test scores/weights to the saved BDT reference), required per-tree `abcd_branches` (for example `{"fat2": ["ScoutingFatPFJetRecluster_sphere_mass"], "fat3": ["ScoutingFatPFJetRecluster_sphere_mass"]}`) whose entries must exist in the copied BDT `selection.json` thresholds, and optional per-tree `a_region_shape_branches` entries for normalized per-class branch-shape plots in each signal bin and the A-union.
- **[plotting/config.json](plotting/config.json)** — controls data_mc.py: `submit_trees`, `sample_config`, `convert_branch_config`, `bdt_root` (per-tree path pattern, points at the BDT tree output dir that already contains the copied `config.json` / `selection.json`), `output_root` (per-tree output dir pattern), `data_samples` (list of data sample names whose entries must exist in `src/sample.json`; data reads are not capped and mixed patterns are rewritten to the non-mixed `data` directory), `default_bins` (default histogram bin count), `validate_bdt_test_scores` (default `true`; compare derived score predictions to the saved BDT reference), `plot_bdt_scores` (default `true`; when `false`, skip derived `score_*` plots and allow an optional top-level `class_groups` in `plotting/config.json` to replace the copied BDT config's groups), and `event_reweight_branches` (per-tree dict `{tree_name: [branch, ...]}` of reweight branches multiplied into each MC event's weight; default `{"fat2": ["weight_pu"], "fat3": ["weight_pu"]}`; data samples are unaffected).
- **[plotting/branch.json](plotting/branch.json)** — plotting config split by tree (`fat2` / `fat3`). Each tree can define `skip_branches` and a `branches` map. Inside `branches`, each ROOT or derived score branch override can set `bins`, `x_range`, `y_range`, `logx`, `logy`; derived score branch names are `score_{class_name}`. Unset fields fall back to defaults. The file is intended to hold a few explicit examples that can be copied when adding new plot formatting rules later.
- **[combine/config.json](combine/config.json)** — `combine.C` settings: `channels` (list of `{name, root_file, bdt_root}` — each `root_file` is the `qcd_abcd_yields.root` output of `mode=5` for one channel, and each `bdt_root` is that channel's trained tree output directory; `combine.C` reads `class_groups` from every channel's copied `config.json`, resolves each config's `sample_config`, and requires the resulting class/sample signal/QCD definitions to match across channels, while allowing each channel to have its own SR count), `output_dir`, optional `combine_cmd` and `combine_cards_cmd` (defaults `combine` / `combineCards.py`), `use_root_covariance` (default `false`; combine reads `srN/yield` one-bin histograms and writes each SR as an independent counting bin, without turning ROOT covariance into nuisances), `eigen_rel_cutoff` (used only when `use_root_covariance=true`, dropping eigenmodes with `λ ≤ cutoff × max(diag(cov))`; default `1e-10`), `rescale_shape_modes_to_positive` (used only when covariance nuisances are enabled; default `true`), and `keep_work` (keep the generated datacards under `output_dir/work/`; default `true`).

## Model Training Details

- `selections/BDT/train.py` only trains on the samples explicitly listed in `class_groups`.
- The number of classes is inferred dynamically from `class_groups`; no fixed 5-class assumption is baked into training.
- A class is treated as `single` for plotting if every sample in that class has `is_signal=true`; otherwise it is treated as `background`.
- For each sample, the code first counts all entries across all matched ROOT files in the chosen tree, then defines a fixed sequential split: the first `train_fraction` goes to training and the remaining tail goes to testing. The split is defined on the concatenated sample entry order across files, so `test_ranges.json` can be used later to recover the exact test subset.
- In `train.py`, `entries_per_sample` only caps how many events are actually loaded from the training side of that fixed split. The test side is always the full tail of the sample.
- Training events are shuffled after loading; test events keep their original order.
- Sample weights are computed separately for the training and test splits, immediately after reading and before any model threshold cuts:
  `target_total       = xsection * tree_entries_total / raw_entries`
  `per_event_weight   = raw_w * target_total / Σ raw_w_loaded`
  where `tree_entries_total` is the total number of entries in the chosen tree across all of that sample's ROOT files (same value for the training and test splits of a given sample), and `raw_w` is the per-event product of the tree's `event_reweight_branches` entries (default `weight_pu`) read on raw values before clip/log/threshold. The denominator `Σ raw_w_loaded` is summed over the events actually read on that side of the split, so the sample total `Σ weight = target_total` regardless of raw_w's magnitude — raw_w only reshapes the per-event distribution inside the sample. With an all-ones `raw_w` this reduces to a constant per-event weight.
- Within each class, the ratio of `target_total` between samples is proportional to `xsection * tree_entries_total / raw_entries`. These per-sample raw weights are frozen before any model threshold cuts, so threshold efficiency changes the post-cut class and sample composition naturally.
- If a per-tree `qcd_ht_training_weight_step` is positive, `train.py` multiplies only its internal `weight` column for samples named like `qcd_ht*` by `1 + rank * step` in increasing HT order (`rank=0` for the lowest configured QCD HT sample). The original `weight_physics` column and all saved prediction-reference weights remain unscaled, and the later class-balancing step still makes each class total equal while preserving the adjusted QCD internal sample proportions.
- The reweight branches are loaded alongside the feature branches, consumed solely to build `raw_w`, then dropped from the DataFrame — they never enter model training, standardisation, or threshold filtering. Missing reweight branches in the input ROOT files raise `KeyError`, and a non-positive `Σ raw_w_loaded` raises `RuntimeError`.
- Any branch that appears in `selection.json`'s `thresholds` block or in the per-tree `decorrelate` list but is NOT declared in `branch.json` is still read from the ROOT files (alongside the `branch.json` features and the reweight branches) so that `filter_X` can cut on it in the relevant view and the decorrelation step can reference it. After `filter_X`, threshold branches that are not in `decorrelate` are dropped from the DataFrame so the model input feature set remains strictly defined by `branch.json` (decorrelate branches stay in `X` because the training backend separates them into `Z` for decorrelation and trains only on the remaining `branch.json` columns).
- `train.py` builds two threshold views when a configured `decorrelate` branch also appears in `selection.json` thresholds. The training view removes those decorrelate-branch threshold conditions except that any decorrelate branch named `ScoutingFatPFJetRecluster_msoftdrop_*` with a selection threshold is kept with a loose `(0, decor_msoftdrop_training_max)` cut (default 200), and is used for model training, early stopping, decorrelation-loss state, and the training/test class balancing. The full evaluation view reapplies the original decorrelate-branch thresholds on top of the training view and is used for ordinary branch distributions, ROC, score distributions, feature importance, `feature_corr.pdf`, and `test_reference_signal_region.npz`.
- After training-threshold/sentinel filtering, class totals are rescaled separately within the training split and within the test split so every class has the same total weight inside that filtered split, with each class total scaled to `N_filtered / N_classes` so the overall XGBoost weight scale stays close to the filtered event count instead of the old large fixed constant.
- This post-threshold class balancing preserves the filtered per-sample proportions inside each class for the training-threshold view: each sample keeps the same relative share it had after the fixed pre-cut `raw_w × target_total / Σ raw_w_loaded` weighting and the non-omitted threshold efficiency losses; only the class-level normalisation changes.
- Threshold/sentinel filtering in `filter_X` is applied **only** to branches that appear as keys in the threshold dictionary passed to that call. For each such branch, events with sentinel values (`< -990`) are dropped and the threshold condition is enforced. Branches that are not in that active threshold dictionary are never inspected, so an event with a sentinel value in (for example) a lepton branch is still kept as long as the active threshold view does not target that lepton branch.
- If `decorrelate` is non-empty and `decor_lambda > 0`, `train.py` trains in two stages. In BDT mode, stage 1 uses native `multi:softprob` without decorrelation and stage 2 resumes from the saved stage-1 best model for `n_estimators_decorr` additional rounds with the custom multiclass objective. In NN mode, stage 1 trains a weighted PyTorch MLP with `objective_loss = weighted_CE` on class-balanced mini-batches using sampling-corrected event weights, and stage 2 resumes from the saved stage-1 best MLP for `epochs_decorr` epochs with `objective_loss = weighted_CE + scaled_smooth_CvM_decorrelation` on the same sampler. BDT chooses stage-1 best on test `classification_loss` and stage-2 best on test `total_loss`; NN chooses both stage-local best epochs on epoch-end test `objective_loss`. If decorrelation is disabled, stage 2 is skipped and the stage-1 model is promoted to the main output path.
- In BDT mode, `classification_loss` is the sum-scale weighted softprob loss built from the class-balanced unit-scale training weights (`Σ w·(-log p_true)`), while `mlogloss` is the weighted average of that same quantity (`Σ w·(-log p_true) / Σ w`). BDT stage 1 receives transformed probabilities from XGBoost's builtin objective and BDT stage 2 receives raw margins from the custom objective. In NN mode, `train_objective_loss` and `test_objective_loss` are epoch-end eval-mode full-split batch objectives, not averages of the update-time loss scalars; `backward()` uses the same objective formula on class-balanced mini-batches with sampling-corrected event weights so the balanced sampler still targets the same weighted objective. The component `weighted_ce_loss` is recorded in both stages, and `decorrelation_loss` is non-zero only in stage 2.
- In BDT mode, `regularization_loss` remains a diagnostic quantity and is reconstructed from the current trees in the same native tree-solver parameterization as XGBoost: `gamma` times the number of leaves, plus the `reg_lambda` / `reg_alpha` penalties evaluated on the unshrunk leaf weights (`leaf / eta` for the stage that produced that boosting round). In NN mode, optimizer `weight_decay` is applied through native AdamW decoupled updates and is not represented as a separate logged scalar loss. NN `objective_loss = weighted_CE + decorrelation_loss` with `decorrelation_loss = 0` in stage 1, while BDT keeps the legacy `total_loss = classification_loss + decorrelation_loss` diagnostic.
- When stage 2 is active and both `lr_reduce_patience` and `min_learning_rate` are positive, the stage-2 monitor suppresses early stopping while `eta > min_learning_rate`; after `lr_reduce_patience` consecutive non-improving rounds it halves `eta` (floored at `min_learning_rate`), logs the reduction, resets both stale counters, and only begins enforcing the normal `early_stopping_rounds` threshold once that floor has been reached.
- In the custom-objective decorrelation modes (`smooth_cvm` and `cvm`), the BDT decorrelation term is multiplied by one fixed train-split scale calibrated from the saved stage-1 best model, using `(cls_loss_stage1 + reg_loss_stage1) / max(raw_decor_loss_stage1, ε)`. NN mode supports `smooth_cvm` and calibrates with the stage-1 batch-averaged weighted CE, `cls_loss_stage1 / max(raw_decor_loss_stage1, ε)`, where `raw_decor_loss_stage1` is the same mini-batch smooth-CvM objective used by NN training and epoch-end train/test evaluation. This keeps `decor_lambda` controlling the decorrelation term relative to the same loss definition used by NN `objective_loss`. `smooth_cvm` is the default differentiable mode: it matches the old CvM objective conceptually by comparing class-wise score-efficiency curves across decorrelation-variable bins, but replaces the hard bin/CDF steps with smooth sigmoid surrogates so the recorded decorrelation loss, objective loss, and training gradient all refer to the same smooth objective. `cvm` keeps the original hard-bin CvM-style loss and its legacy surrogate gradient for backward-compatible BDT studies. Early stopping remains stage-local, using test `classification_loss` for BDT stage 1, test `total_loss` for BDT stage 2, and epoch-end test `objective_loss` for both NN stages.
- `train.py` saves BDT stage-1/final models as `{tree}_model_stage1.json` and `{tree}_model.json`, and NN stage-1/final models as `{tree}_model_stage1.pt` and `{tree}_model.pt`; comparison plots keep `_cls` / `_decorr` suffixes for the stage-1 and stage-2 models respectively. Downstream scripts call the shared `selections/BDT/model_io.py` loader, choose JSON/PKL BDT models or PyTorch `.pt` checkpoints from the copied `model_type`, and apply the multiclass softmax explicitly before using model scores.
- After writing the final model, `train.py` also writes `test_reference_signal_region.npz`, `test_reference_qcd_est.npz`, and `test_reference_qcd_est_full.npz`. Each file stores the exact test-split feature order, sample order, class labels, pre-lumi physics weights, predicted class probabilities, and per-array tolerances for the corresponding downstream preprocessing chain. `test_reference_signal_region.npz` uses the full evaluation thresholds, including original decorrelate-branch thresholds that were omitted or loosened in training, so its stored weights and row set match the downstream signal-region/data-MC score path. When their `validate_bdt_test_scores` option is true, `signal_region.py`, `qcd_est.py`, and the derived-score path in `plotting/data_mc.py` multiply the stored reference weights by their local configured luminosity before comparing them to the reconstructed physical weights; any remaining mismatch is treated as fatal and the script exits instead of silently proceeding.
- `background_estimation/qcd_est.py` logs timing and size diagnostics around full-reference validation, including full test-set feature copying, standardisation, model prediction, `.npz` reference loading, label/weight comparisons, and probability comparison. Preserve those logs when editing this path because large QCD test splits can otherwise look stalled after the `Validating full test-set prediction reference` message.
- ROC and score-distribution plots adapt to the configured classes and are written separately for the stage-1 baseline (`*_cls.pdf`) and stage-2 final model (`*_decorr.pdf`) when both stages exist. These ordinary comparison plots use the full evaluation thresholds even when the training objective omitted or loosened a decorrelate-branch threshold. When both signal-like and background-like classes exist, one ROC PDF is written per signal class, overlaying every background class in a distinct color (test curves solid, train curves dashed), and one score PDF is written per signal-background pair. When there is no signal/background split, the code falls back to one ROC PDF per class (treating it as the "signal" against all other classes) and all-pair score distributions.
- After training, `train.py` copies `config.json`, `branch.json`, and `selection.json` into the tree output directory so that `signal_region.py` can run self-contained from that directory.

## Signal Region Scan Details (`signal_region.py`)

- Reads all parameters from `scan.json` (configurable via `SCAN_CONFIG_PATH` env var).
- Loads test events from `test_ranges.json` (exact same split as used in training).
- Physics weights: `target_total = lumi × xsection × total_tree_entries / raw_entries` and `per_event_weight = raw_w × target_total / Σ raw_w_loaded`, where `total_tree_entries` is all entries across all ROOT files for that sample in the chosen tree (train + test combined), and `raw_w` is the per-event product of the tree's `event_reweight_branches` in the trained-model config copy (read on raw values, before any clip/log/threshold, and dropped from the DataFrame after `raw_w` is built). The sample total `Σ weight = target_total` regardless of raw_w; missing test split files/trees, failed segment reads, non-positive `raw_entries`, or non-positive `Σ raw_w_loaded` raise `RuntimeError`. No class rebalancing is applied.
- Preprocessing (clip, log transform, threshold filter) is identical to train.py's full-threshold evaluation test-split logic.
- Threshold/sentinel filtering matches `train.py`'s downstream evaluation view: only branches that appear in `selection.json`'s `thresholds` block are inspected, including decorrelate branches that may have been omitted from the training objective, and only those branches can drop events for sentinel values (`< -990`) or failed threshold conditions.
- Branch loading mirrors `train.py`: threshold or decorrelate branches that are not in `branch.json` are still read from the test split ROOT files for filtering and decorrelation, then the threshold-only ones (not in `decorrelate`) are dropped from `X` before the existing decorrelation/model-inference step runs.
- Decorrelated features (e.g., `msd8_1`) are excluded from the model input, same as during training.
- Scan dimensions come from `score_axes`: `independent` uses `p(class_0)` through `p(class_{NUM_CLASSES-2})`, while `all` includes every class probability, including the final class so direct upper/lower cuts on that class can be represented.
- Each signal region is a general axis-aligned high-dimensional rectangle: every axis has its own `[low, high)` (`high == 1.0` is open-ended). The previous "single slim slice + other axes open to 1" restriction has been removed; downstream `qcd_est.py` already consumes the per-axis `_low`/`_high` columns from `signal_region.csv`.
- Significance formula per region: `Z = sqrt(2 * [(S+B)*ln(1+S/B) − S])` (profile-likelihood). Error propagated via partial derivatives.
- Combined objective: `Z_comb = sqrt(Σ Z_i²)` over the N selected non-overlapping regions. The final selection is global over the generated candidate list rather than sequential: it searches K-region combinations and maximizes `Σ Z_i²`, which is exactly the script's existing combined-significance objective.
- Per-axis edge candidates: total, signal-only, background-only, and unweighted score quantiles are combined with tail-heavy quantiles, capped at `max_edge_candidates_per_axis` distinct edges while always including `0.0` and `1.0`. These edges are the global candidate boundary set.
- Beam coordinate search: seeds include the full box, low/mid/high-tail high-side and low-side single-axis seeds from `seed_quantiles`, and up to `seed_intervals_per_axis` exact single-axis bounded `[low, high)` interval seeds per score axis. `multi_axis_seed_max_axes` / `multi_axis_seed_max_seeds` can add bounded combinations of those one-axis seed intervals so the search starts from simultaneous lower/upper cuts on multiple score axes instead of relying only on later coordinate updates. Optional `forbidden_regions` are still supported for compatibility, but the normal workflow no longer performs one scan per SR. For up to `coordinate_rounds`, every beam state updates every axis by histogramming events that pass the other axes, sweeping all `(a < b)` intervals in `O(K²)`, and keeping the best `top_intervals_per_axis` exact intervals for that axis. Independent per-axis/per-state interval scans may use `max_threads`, but their outputs are merged back into the pool in deterministic scan order so threading does not change the finite candidate set. The beam keeps the strongest states while preserving some non-overlapping diversity, and every valid visited rectangle is added to the candidate pool.
- Compatibility expansion: after the first shared beam pass, the scan takes up to `compatibility_seed_anchors` high-Z anchors chosen by distinct event masks and creates seeds that are guaranteed to be geometrically non-overlapping with each anchor on one separating score axis. It then runs additional coordinate updates while keeping that separating axis fixed, so the pool contains candidates that are explicitly optimized as possible partners for a slightly lower first region. These candidates still enter the same global candidate list; they are not selected greedily.
- Local event-threshold refinement: up to `local_refine_top_candidates` regions are refined for `local_refine_rounds` passes. With `local_refine_diverse_masks=true`, the refinement seed list is chosen by distinct event masks rather than raw Z order, preventing hundreds of geometric variants of the same event set from consuming all refinement passes. Around each current low/high boundary, the scan injects nearby real event score values from the cached per-axis score values (`local_refine_neighbor_edges`) and again performs exact one-axis interval sweeps, adding each valid refined rectangle to the pool.
- Candidate pool: every region is deduped only by rounded `(low, high)` during generation and gated by `B ≥ min_bkg_weight`, `S > min_signal_weight`, and optional event-count minima. No candidate-pool or global-candidate count limit is applied, so candidates are not removed by single-region `Z`. Before global selection, every candidate is shrunk to an event-preserving minimal score box; exact event-mask/canonical-box deduplication then removes only candidates that select the same exact event mask and shrink to the same rounded canonical box. This keeps `S/B/Z` unchanged on the scan events while avoiding deletion of merely lower-ranked but complementary candidates.
- Global selection: `signal_region.py` compiles and loads `openmp_region_select.cpp` into `output_dir/.openmp/` when `max_threads > 1`. The helper first runs a bounded beam search with `global_beam_width` to get a strong incumbent, then runs branch-and-bound over the candidate list with an admissible upper bound that ignores future mutual overlaps but preserves compatibility with already selected regions. Compatibility uses the same exact half-open `[low, high)` interval intersection as the Python event-mask definition; touching boundaries are allowed, but any positive intersection is treated as overlap. `branch_bound_max_nodes=0` disables the node cap, and `branch_bound_time_limit_seconds=0` disables the wall-time cap. If the search completes, the selected set is exact for the finite candidate list; if a cap is hit, the script reports `Z_best`, a conservative `Z_upper_bound`, and the resulting `delta_Z` certificate. If OpenMP build/load fails or `max_threads == 1`, the same search runs in Python. Progress logs report beam rounds, local refinement progress, candidate-pool size, global selector type, completion status, node count, overlap checks, and final `Z_comb`.
- Empty-bin score-axis expansion: after global selection and the non-overlap check, every selected SR is expanded in order (SR1 first, then SR2, …). For each SR, signal-class score axes have their upper bound pushed toward `1.0` and background-class score axes have their lower bound pushed toward `0.0`, but only into space that is empty in MC under that SR's other-axis cuts. Each expansion is constrained so that (a) the SR's exact selected event mask is preserved, and (b) the expanded box remains geometrically non-overlapping with every other selected SR (already-expanded earlier ones and not-yet-expanded later ones). The other expansion direction (signal-axis low / background-axis high) is intentionally **not** expanded. Per-bin `S`, `B`, `Z` are recomputed after expansion and stay numerically identical to the pre-expansion values; only the empty-side score-axis bounds change in the per-SR report and in `signal_region.csv`. The script logs how many signal-axis high bounds and background-axis low bounds were widened.
- Signal class: any class where all member samples have `is_signal=true`. Background: all other classes.
- Output files: `sr_score_*.pdf`, `scores_no_regions.pdf`, `scores.pdf`, `scores_no_regions_radial_equalized.pdf`, `scores_radial_equalized.pdf`, and `signal_region.csv` all go to `output_dir`. The CSV stores one row per selected signal region and expands the high-dimensional bin definition into per-axis `{axis_name}_low` / `{axis_name}_high` columns.

## `run.sh` Behavior

[run.sh](run.sh) supports eight modes:

- `mode=0` compiles `selections/convert/convert_branch.C`, then runs each selected sample as a sequence of bounded batch invocations.
- `mode=1` compiles and runs `selections/weight/weight.C`.
- `mode=2` runs `selections/BDT/train.py` with `BDT_CONFIG_PATH` pointing to the chosen config file.
- `mode=3` runs `selections/signal_region/signal_region.py` with `SCAN_CONFIG_PATH` pointing to the chosen config file.
- `mode=4` runs `plotting/data_mc.py` with `PLOT_CONFIG_PATH` pointing to the chosen config file.
- `mode=5` runs `background_estimation/qcd_est.py` with `QCD_EST_CONFIG_PATH` pointing to the chosen config file.
- `mode=6` compiles and runs `selections/mix/mix.C` with `MIX_CONFIG_PATH` pointing to the chosen config file.
- `mode=7` compiles and runs `combine/combine.C` with `COMBINE_CONFIG_PATH` pointing to the chosen config file. It does not take sample arguments and runs once per invocation.

For `mode=0`, `mode=1`, and `mode=6`, the script resolves the sample list from JSON configs, then runs jobs with `MAX_CONCURRENT_JOBS` parallelism (default 1). For `mode=0`, each per-sample job first runs `convert_branch <sample> --batch-count`, then runs `convert_branch <sample> <batch_index>` for every zero-based batch index so no convert process reads more than one batch of input files. Log output goes to `selections/convert/log.txt`, `selections/weight/log.txt`, `selections/BDT/log.txt`, `selections/signal_region/log.txt`, `plotting/log.txt`, `background_estimation/log.txt`, `selections/mix/log.txt`, or `combine/log.txt` depending on mode. All eight modes use the same timestamped run-log style in `run.sh`; `mode=0`, `mode=1`, and `mode=6` log per-sample `started` / `finished` records, while `mode=0` also logs per-batch `running sample=... batch=X/Y` records. `mode=2`, `mode=3`, `mode=4`, `mode=5`, and `mode=7` log one `started` / `finished` record for the whole job with an explicit exit `status=`. Inside `selections/BDT/train.py`, `selections/signal_region/signal_region.py`, `plotting/data_mc.py`, and `background_estimation/qcd_est.py`, the script output follows the same concise stage-by-stage `Running ...`, `Wrote ...`, and `Runtime error: ...` style. The compiled binary is removed on exit for the C++ modes. OpenMP is auto-detected for intra-job parallelism when compiling the C++ tools.

`run.sh` also installs an `EXIT` trap that, after the job's final `finished` log line is written, copies the run-log into the program's configured output directory for every mode that has one — `mode=1` (`output_root`), `mode=2` and `mode=4` (per-tree `output_root` template expanded against `submit_trees`), and `mode=3`, `mode=5`, `mode=7` (`output_dir`). The destination filename is always `log.txt` inside that output dir; if a destination dir does not exist (e.g., the script aborted before creating it), the copy is skipped with a warning. `mode=0` (`convert_branch`) and `mode=6` (`mix`) are intentionally excluded. The copy happens both on success and failure so that the final log lines `[finished job=… status=…]` are always preserved, but the post-copy bookkeeping lines (`copied log to …`) only appear in the source `log.txt`, not in the copy. Path resolution mirrors the scripts themselves: relative `output_root` / `output_dir` values are resolved against each mode's `WORK_DIR`, which is the same directory each script uses as its `_SCRIPT_DIR`.

## C++ Expression Engine (convert_branch.C)

The selection and branch formulas in JSON are parsed by a mini expression engine inside [selections/convert/convert_branch.C](selections/convert/convert_branch.C). Supported syntax:
- Arithmetic/logical operators, comparisons
- Functions: `pt(obj)`, `eta(obj)`, `phi(obj)`, `mass(obj)`, `abs()`, `min()`, `max()`, `size(coll)`, `deltaR(a,b)`, `min_deltaR(self, coll)`, `relPtDiff(a,b)`
- Collection indexing: `ak8[0]`, `ak4[1]`
- `self` / `other` keywords in per-object selection strings

## Physics Context

- **Signal:** VVV hadronic decays — WWW, WWZ, WZZ, ZZZ, and VH(->WW) associated production
- **Trigger:** `DST_PFScouting_JetHT` scouting stream
- **Jets:** AK8 fat jets (`ScoutingFatPFJetRecluster`) and AK4 jets (`ScoutingPFJetRecluster2`)
- **Signal regions:** `fat2` (2 AK8 jets, ≥2 AK4 jets) and `fat3` (≥3 AK8 jets)
- **QCD background:** estimated with ABCD method using model score as discriminant
- **Pileup corrections:** three variations (nominal/low/high) for systematic uncertainty
