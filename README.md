# ScoutingVVVTools

CMS scouting VVV analysis workflow for pileup reweighting, branch conversion with jet energy corrections, optional sample-entry mixing, BDT/NN training (with k-fold scoring), signal-region optimization, QCD ABCD estimation, systematic uncertainties, data/MC plotting, and CMS combine significance/limits.

## Pipeline order

1. `mode=1`: build pileup-weight CSV files.
2. `mode=0` with `selections/convert_ttbar_cr/config.json`, then `selections/jms_jmr/jms_jmr_fit.py`: convert the semileptonic ttbar control region with the same jet corrections (without JMS/JMR) and fit the AK8 soft-drop mass scale and resolution (JMS/JMR) that the signal-region conversion applies.
3. `mode=0`: convert the selected NanoAOD-style inputs into the five analysis trees `boosted3`, `boosted2_resolved`, `boosted2_unresolved`, `boosted2_leptonic_1lep`, and `boosted2_leptonic_2lep`, with the official jet energy corrections, Type-1 MET, JMS/JMR, and, for MC, one `<tree>__<variation>` tree per jet systematic variation in the same files (see [Jet energy corrections](#jet-energy-corrections)). The merge writes the generator-weight sums into `src/sample.json` (see [Generator weights](#generator-weights)).
4. `mode=6` (optional): shuffle each selected MC sample across its ROOT chunks while preserving chunk sizes and filenames.
5. `mode=2`: train the BDT (or PyTorch NN) per tree. The production config trains 5 k-fold rotations per tree; then `selections/BDT/score_kfold.py` (or `selections/BDT/submit_score_kfold.sh`) writes the score cache that gives every MC event a score from a model that never saw it.
6. `selections/theory_weights/generator_sums.py`, then `mode=8`, `mode=9`, `mode=11`–`mode=14` with the `config_inclusive.json` of each syst directory (no signal regions, output `output/inclusive/`): the inclusive systematic ratios used by the signal-region optimizer.
7. `mode=3`: optimize the signal regions per tree and write `signal_region.csv`.
8. `mode=5`: run the QCD ABCD estimation and write the combine inputs (`background_estimation/submit_sr_qcd_est.sbatch <tree>` runs steps 7 and 8 in one job).
9. `mode=8`, `mode=9`, `mode=11`–`mode=14` with the signal regions: theory, pileup, JES, JER, JMS, and JMR yield ratios per MC sample, tree, and signal region.
10. `mode=4`, `mode=10`, `plotting/sr_sensitivity.py`: data/MC, class-shape, and signal-region sensitivity plots.
11. `mode=7`: run the CMS combine wrapper to compute expected significance and AsymptoticLimits per signal class / signal sample / combined, both with the MC-true QCD and with the ABCD QCD prediction, with every systematic uncertainty of [Systematic uncertainties](#systematic-uncertainties).

`selections/b_veto/` and `systematics/` are separate studies and are not launched through `run.py`.

## `run.py`

Usage:

```bash
python3 run.py <mode> [config.json] [sample1 sample2 ...] [--slurm ...]
```

`run.py` is the job dispatcher; the older `run.sh` does not link correctionlib and cannot build the current `convert_branch.C`. For the C++ modes it compiles the tool in its directory (auto-detecting OpenMP, and correctionlib through `python3 -c "import correctionlib"`, whose library directory is embedded as an rpath) and, for local runs, deletes the compiled binary at exit; `selections/convert/convert_branch` is a tracked file, so build test binaries elsewhere. Logs go to `log.txt` in each mode's directory (or `log_<config stem>.txt` for a non-default config).

Examples:

```bash
python3 run.py 1
python3 run.py 0
python3 run.py 0 selections/convert/config.json www qcd_ht2000
python3 run.py 0 selections/convert_ttbar_cr/config.json
python3 run.py 6
python3 run.py 2 --slurm
python3 selections/BDT/score_kfold.py selections/BDT/boosted3
python3 run.py 3 selections/signal_region/config_hist_boosted3.json
python3 run.py 5 background_estimation/config_boosted3.json
python3 run.py 8
python3 run.py 11
python3 run.py 4 plotting/config.json
python3 run.py 7 combine/config.json
```

Modes:

- `mode=0`: compile and run `selections/convert/convert_branch.C`.
  Input: `selections/convert/config.json`, `selections/convert/branch.json`, `selections/convert/selection.json`, `src/sample.json`, the pileup CSVs from `mode=1`, the jet-correction files of the `jet_pt_correction` block, and the JMS/JMR fit result.
  Output: converted ROOT files under `{output_root}/{signal|bkg|data}/` (`{sample}.root`, or `{sample}_0.root`, `{sample}_1.root`, … above `max_output_file_size_gb`), plus `selections/convert/log.txt`. Each file holds the five nominal analysis trees and, for MC, the `<tree>__<variation>` jet-systematic trees. `run.py mode=0` asks `convert_branch.C` for the batch count and invokes it once per batch, so each invocation reads at most `CONVERT_FILES_PER_BATCH` input files (`--slurm-files-per-job` for SLURM, default 50), or `actual_thread_count * 32`. The input file list is snapshotted once per sample in `{output_root}/{sample_group}_tmp/{sample}.files`, so a dataset that grows during the run cannot shift the batches. Each batch is written to `{output_root}/{sample_group}_tmp/{sample}_X.root` with `.raw_entries`, for data `.lumis`, and a `.meta` completion record holding the input-slice and configuration hashes and the generator-weight sums. `resume_successful_batches` (default `true`) skips only complete batches written from the same file slice, binary, and configuration. The merge runs only when every batch succeeded (a failed batch makes the run exit non-zero; rerun to retry it), fast-merges the batch files, checks the per-tree entry counts, and then writes `raw_entries`, the `weight_pu*_mean` values, and the `sum_genweight*` sums into `src/sample.json` (under a file lock, so parallel merges are safe). A remote input that cannot be opened after five retries fails a data batch (it would lose luminosity) and is skipped and reported for MC. For data, the lumi mask (`lumi_mask`) is applied before the preselection and the processed lumisections are written to `{sample}_processed_lumis.json`. `selections/convert/check_conversion.py` checks the batch and merged outputs, including every configured variation tree of an MC sample and its listed branches, and prepares recovery jobs.
  The pileup root files can be obtained from using wget on these links: https://cms-service-dqmdc.web.cern.ch/CAF/certification/Collisions24/PileUp/dataPileupHistogram-2024CDEFGHI_Golden-66000ub.root, https://cms-service-dqmdc.web.cern.ch/CAF/certification/Collisions24/PileUp/dataPileupHistogram-2024CDEFGHI_Golden-69200ub.root, https://cms-service-dqmdc.web.cern.ch/CAF/certification/Collisions24/PileUp/dataPileupHistogram-2024CDEFGHI_Golden-72400ub.root
- `mode=1`: compile and run `selections/weight/weight.C`.
  Input: `selections/weight/config.json` and `src/sample.json`.
  Output: pileup CSV files under the configured `output_root`, plus `selections/weight/log.txt`. Like `convert_branch.C` for MC, a remote input that still cannot be opened after five retries (5 s apart), or a file without the tree or the pileup branch, is skipped with a warning; the run fails only when every file is skipped. Each run writes the skipped files (possibly none) to `pileup_<sample>_skipped.txt` next to the CSV.
- `mode=6`: compile and run `selections/mix/mix.C`.
  Input: `selections/mix/config.json`, `src/sample.json`, and the converted MC ROOT files from `mode=0`.
  Output: shuffled ROOT files under `output_root/{signal_mixed|bkg_mixed}/`, preserving the original chunk filenames and per-chunk entry counts, plus `selections/mix/log.txt`. Missing input files are fatal. Each tree is rewritten through a `TChain` with a deterministic block shuffle seeded by `random_state` (shuffled contiguous blocks plus an in-block cyclic rotation, block size `clamp(total_entries / 512, min_block_entries, max_block_entries)`, defaults `32` / `4096`), and per-chunk and total entry counts are validated. Read the mixed files with `input_pattern = {input_root}/{sample_group}_mixed/{sample}.root`.
- `mode=2`: run `selections/BDT/train.py`.
  Input: `selections/BDT/config.json`, the converted ROOT files resolved from its `input_root` / `input_pattern` (the checked-in config reads the unmixed `dataset_hybrid_leptonic`), and `src/sample.json`.
  Output: one model directory per tree under `output_root` (with `kfold`: one `fold<r>/` per rotation). With `model_type: "bdt"` it holds `{tree}_model.json` and `{tree}_model_stage1.json`; with `model_type: "nn"` PyTorch checkpoints `{tree}_model.pt` / `{tree}_model_stage1.pt` (PyTorch needed only then). It also holds copies of `config.json` / `branch.json` / `selection.json`, `test_ranges.json` (the split, and for k-fold the blocks and files), the prediction references `test_reference_signal_region.npz`, `test_reference_qcd_est.npz`, `test_reference_qcd_est_full.npz` and, with an eval split, `eval_reference_signal_region.npz`, the loss plots, stage-tagged comparison plots (`importance_*`, `roc_*`, `score_*`, `decor_corr_*`, `decor_score_vs_branch_*`, `decor_branch_shapes_by_signal_score_*`, each as `_cls` for stage 1 and `_decorr` for stage 2), `feature_corr.pdf`, and `branches/` with one normalized per-class distribution per input branch, plus `selections/BDT/log.txt`.
  Splits: every sample is split into train / eval / test (`train_fraction`, `eval_fraction`; 0.6 / 0.2 in production); the eval split monitors early stopping and the learning-rate schedule. With `kfold: K` (production 5) the entries are cut into K blocks and rotation `r` trains on K − 2 blocks, monitors on block `r − 1`, and tests on block `r`. `train_events_per_class` (production 3,000,000 for `Top`) reads the training events of a class as random blocks shared among its samples in proportion to their physics totals.
  Training: stage 1 is a native multiclass BDT (or weighted NN); stage 2 continues it with the smooth-CvM decorrelation loss, which makes the QCD class probabilities independent of the `decorrelate` branches (the ABCD variable `msoftdrop_1` among them) on the QCD events; with `decor_eff_normalize`, thresholds in the score tails get equal weight. The decorrelation branches keep a loose `(0, decor_msoftdrop_training_max)` window during training, while the evaluation plots and references use the full `selection.json` thresholds. Per-tree options: `training_weight_cap` (production 20) caps very heavy training weights, `qcd_ht_training_weight_step` and `training_sample_weight_scales` rescale samples in the training only, `class_balance_power` softens the class balancing. Physics weights stay signed; the classifier uses `|w| × Σw / Σ|w|` per sample and split (see [Generator weights](#generator-weights)).
  With `--slurm`, one SLURM job per tree (and k-fold rotation) is submitted (`BDT_TREES`, `BDT_FOLD`; default `--slurm-cpus 32 --slurm-mem 200G`).
- k-fold score cache (not a `run.py` mode): `python3 selections/BDT/score_kfold.py <tree root> [sample ...] [--branches a,b]`, or one SLURM job per sample with `selections/BDT/submit_score_kfold.sh <tree root> [--after jobids] [--branches a,b]`. It writes `<tree root>/kfold_scores/<sample>.npz` (each event's out-of-fold probabilities, its pre-lumi physics weight with every entry read, and the threshold and decorrelation branches) after checking every fold's probabilities against that fold's `test_reference_qcd_est_full.npz`. The cache is refused after a retraining; after a change of a sample's `xsection` or `sum_genweight_pu` (and for caches written before the 2026-10-13 merge, which used another normalization) rescore that sample. The signal-region optimizer, `qcd_est.py`, the syst scripts, and the plots use every cached MC event of a k-fold model.
- `mode=3`: run `selections/signal_region/signal_region_hist.py`, the signal-region optimizer (`signal_region.py` is its library of data loading, model inference, reference checks, reporting, and plotting).
  Input: one config per tree, `selections/signal_region/config_hist_<tree>.json` (`config.json` is the `boosted3` one), naming the trained model directory from `mode=2` (for k-fold models the score cache), the inclusive `*_syst_yields.json` of modes 8, 9, and 11–14 under `<syst dir>/output/inclusive/` (`background_syst_jsons`, plus `lumi_unc` and `trigger_unc`), and the cross-section uncertainties `xsec_unc_json` (`combine/xsec_unc.json`). `exclude_samples` leaves samples out of the scan (production: the QCD samples with HT < 400 GeV).
  Objective (the background model of the combine cards): every region gets the Asimov significance with a background uncertainty `Z_A(S, B, V)` (G. Cowan, "Discovery sensitivity for a counting experiment with background uncertainty"). `B` is the background MC; with `abcd_uncertainty` (k-fold models; production: `msoftdrop_1`, control window 20–50 GeV, non-closure 0.2) its QCD part is the per-SR ABCD prediction from the region's control events, `C × TF`. `V` = the correlated background systematics `Σ_k (Σ_c δ_{c,k}·B_c)²` (rows as in the cards: lumi, trigger, theory PDF, ISR, FSR, pileup, JES, JER, JMS, JMR shared by all classes, one QCD-scale and one cross-section row per class; `δ_{c,k}` from the yield-weighted inclusive ratios, the larger of `|R_up − 1|`, `|R_down − 1|`, signed along the up variation; no rows on the data-driven QCD) + the background MC statistics `Σ w²` + with `zero_count_floor` the squared median event weight of every background class without MC events in the box (as combine's zero-count floor) + with `abcd_uncertainty` the uncertainty of the QCD prediction, `TF² × (control-region count + non-QCD MC Σ w² there) + (non-closure × predicted QCD)²`, in place of the QCD MC statistics.
  Steps: coarse grid beam search (`coarse_bin_width`, finer `qcd_coarse_bin_width` on the QCD axis) with disjoint re-seeding; every candidate shrunk to the smallest box holding the same events (in ABCD mode also the same control events) and candidates with identical events merged; branch-and-bound over all candidates maximizing `Σ Z_A²` (OpenMP helper `openmp_region_select.cpp`, Python fallback; `branch_bound_time_limit_seconds`, 4 h in production, after which the upper-bound certificate is reported); exactly N regions (`require_exact_n_regions`); a joint stage that replaces one region at a time by the compatible candidate (among the 256 of highest Z_A) that most increases `Z_joint`, the Asimov significance of all regions fitted together with the correlated systematic rows and the ABCD non-closure (profile likelihood), so correlations and the constraint of the nuisances by other regions enter the choice; fine-grid refinement of the selected boundaries with all acceptance minima (`min_bkg_weight`, `min_signal_weight`, `min_*_entries`), never lowering a region's Z_A and kept only if `Z_joint` does not drop; boundaries in empty score gaps placed with signal-score bounds as high and background-score bounds as low as the same events allow, without overlapping another region; geometric and event-level non-overlap checks. Without k-fold the prediction is validated against the stored reference (`validate_prediction_reference`, default true).
  Output: `signal_region.csv` (one row per SR with per-axis `{axis}_low` / `{axis}_high` bounds, `significance` = Z_A, and `significance_stat`), `sr_score_*.pdf`, `scores_no_regions.pdf`, `scores.pdf`, and their `_radial_equalized` versions inside the configured `output_dir` (`output/<tree>_hist/`), plus `selections/signal_region/log.txt`.
- `mode=4`: run `plotting/data_mc.py`.
  Input: `plotting/config.json`, `plotting/branch.json`, the converted ROOT files from `mode=0`, the trained model directory from `mode=2`, and the `signal_region.csv` files of `mode=3`.
  Output: per tree `{output_root}/{tree}_hists.npz` and, per branch, a physical-normalization PDF (stacked MC, data, MC-statistics and theory bands, Data/MC ratio) and a `_normal.pdf` with data and total MC each scaled to unit area, plus `plotting/log.txt`. The fill stage (`--fill-only`) reads every entry of every file once, with the MC weights of [Generator weights](#generator-weights) and the model scores (k-fold models: each MC event with its own fold, data by event number), applies the `selection.json` thresholds (`--no-selection` skips them) and `plot_thresholds`, and stores every histogram on a fine grid; the plot stage (`--plot-only`) rebins and draws them without reading the inputs. Blinding is on by default: data events inside a signal region (the score boxes of `signal_region_csv` with all thresholds) are removed, MC is not; `--unblind` keeps them, and trees without signal regions must be listed in `unblinded_trees`. `exclude_samples` removes MC samples from every plot (production: the QCD samples with HT < 400 GeV). The model-score histograms are not yet validated against the stored prediction reference.
- `mode=5`: run `background_estimation/qcd_est.py`.
  Input: `background_estimation/config_<tree>.json` (`config.json` is the `boosted3` one), the trained model directory from `mode=2` (k-fold: its score cache), and the `signal_region.csv` written by `mode=3`.
  Output: ABCD summary PDFs and one ROOT file (`qcd_abcd_yields.root`) under the configured `output_dir`, plus `background_estimation/log.txt`. QCD classes are the `class_groups` names containing `qcd`. Region A is the union of the signal-region boxes with every `abcd_branches` threshold passing, B the rest of the pass region, C and D the same in the fail region. `abcd_mode: union` scales the MC-true QCD in each SR by one ABCD factor; `abcd_mode: per_sr` (production) predicts every SR as `C_i × B/D`, with `C_i` the box in the `abcd_control_window` of the fail region (production 20–50 GeV in `msoftdrop_1`), and passes `abcd_per_sr_nonclosure` (production 0.2) to combine. `exclude_samples` (production: the QCD samples with HT < 400 GeV, whose few very heavy events set the transfer factor) leaves samples out of every yield. Without k-fold the model is rerun on the test split and must reproduce `test_reference_qcd_est_full.npz` (weights and probabilities, stored tolerances); a mismatch aborts.
  The ROOT file stores `metadata/signal_regions` (a TTree written with uproot `mktree`; plain dict assignment would write an RNTuple since uproot 5.7, which `combine.C` cannot read), `metadata/sr_csv_hash` (hash of the SR CSV, checked by combine against the systematics), and combine-facing bundles for `samples/*`, `groups/*`, `qcd_predict`, `qcd_true`, `total_predict`, and `total_true`: per SR one-bin `srN/yield`, `srN/stat_error` (`sqrt(Σ w²)` for MC; the prediction's statistical part for `qcd_predict`), `srN/scale_error` (the ABCD scale part), `srN/n_entries` (raw MC events), plus `covariance_total` and `mean_event_weight` (median event weight, used for the zero-count floor). `qcd_predict/abcd_scale` is the MC closure (predicted / MC-true QCD) with `abcd_scale_error`. In `per_sr` mode the file also holds `qcd_predict/{per_sr_abcd, abcd_tf, abcd_tf_error, abcd_nonclosure}` and the control and B/D regions under `control/*` and `abcd_bd/*`. Negative SR yields (possible with signed weights) are written as 0 with a warning. The PDFs stack the ABCD regions by class (`qcd_abcd_region_counts*.pdf`, `qcd_abcd_region_fractions*.pdf`, also with the QCD classes merged), and optional per-tree `a_region_shape_branches` add normalized per-class shapes under `output_dir/a_region_shapes/`.
- `mode=7`: compile and run `combine/combine.C`.
  Input: `combine/config.json` (one channel per tree, each with its `qcd_abcd_yields.root` from `mode=5` and its `bdt_root` from `mode=2`), the `*_syst_yields.json` of modes 8, 9, and 11–14, and `combine/xsec_unc.json`. `combine.C` reads `class_groups` from each `bdt_root` (k-fold: `fold0/config.json`) and resolves its `sample_config` like `qcd_est.py`. The channels must agree on the class order, the signal classes with their samples, and the QCD classes; background classes may list different samples per channel (the wrapper uses their union). Must be executed where `combine` and `combineCards.py` are available (a CMSSW area with `HiggsAnalysis/CombinedLimit`, or on `fasrc` the CVMFS `combine-standalone` image; a `CMSSW_*` area inside the repository is ignored by `.gitignore`).
  Output: `significance.csv`, `limits.csv`, `significance_abcd_mc.csv`, `limits_abcd_mc.csv`, and the per-channel `significance_by_channel.csv`, `limits_by_channel.csv`, `significance_by_channel_abcd_mc.csv`, `limits_by_channel_abcd_mc.csv` (extra `channel` column) under `output_dir`, plus `combine/log.txt`. Each CSV has one row per scenario (combined / per signal class / per signal sample; `scenario_scopes` restricts them). Every SR is one bin of a shape card fitted to the Asimov data (`-t -1`): the MC statistics enter through `autoMCStats`, a background class without MC events in an SR gets a zero-count floor `gmN 0 α` (α = its median event weight, started at 0), and the `_abcd_mc` CSVs replace all QCD classes by the ABCD prediction `bkg_qcd`. With the per-SR ABCD, a second card per channel holds the control regions `C_i` and the regions B and D, whose QCD yields are free parameters, so each SR's QCD is `C_i × B/D` constrained by the control-region counts. The significance uses `--rMin -5 --rMax 10` (with combine's default r ≥ 0 it returned exactly 0 for a valid card); the limits keep r ≥ 0. The nuisances are listed in [Systematic uncertainties](#systematic-uncertainties); an enabled nuisance without its input, an unknown `enabled_nuisances` name, a non-positive kappa, and per-SR ratios computed for other signal regions (SR CSV hash mismatch) stop the wrapper with an error. A scenario that fails is stored as `nan`, the remaining scenarios still run, and the run exits non-zero; missing limit quantiles store `nan` limits; a signal sample without yield in every channel gets significance 0 and infinite limits. `use_root_covariance=true` replaces `autoMCStats` and the floors by eigen-decomposed covariance shape nuisances. The datacards, shape files, and combine outputs stay under `output_dir/work/` unless `keep_work` is `false`.
- `mode=8`: run `selections/theory_weights/theory_syst.py` (PDF, scale, ISR, and FSR ratios of the samples with `has_theory_weights`, from the nominal trees' theory-weight branches, each member normalised to its value over all generated events, so the variations change only the acceptance). The generated-event sums come from `selections/theory_weights/generator_sums.py` (run it once per sample, e.g. `THEORY_CONFIG_PATH=config.json python3 generator_sums.py <sample>`, then `python3 generator_sums.py --merge`), which reads the `Runs` trees (`LHEScaleSumw`, `LHEPdfSumw`, `PSSumw`) of the remote input files listed in the conversion's `{sample_group}_tmp/{sample}.files` and writes the config's `generator_sums_json`.
- `mode=9`: run `selections/pileup_syst/pileup_syst.py` (`weight_pu_up` / `weight_pu_down` against `weight_pu`, each normalized by its own generated-event sum).
- `mode=10`: run `plotting/class_shapes.py` (unit-area shapes per class, same weights and `exclude_samples` as `mode=4`).
- `mode=11`, `mode=12`, `mode=13`, `mode=14`: run `selections/{jes,jer,jms,jmr}_syst/<syst>_syst.py`, thin wrappers around `selections/jet_syst_common/jet_variation_common.py` that compare each `<tree>__<syst>_{up,down}` tree with its nominal tree in the same converted files.
  Every syst script writes `<name>_syst_yields.{json,csv}` under its `output_dir` with, per MC sample and tree, the inclusive up/down ratios and a `regions` entry per signal region (with the `sr_csv_hash` of the SR CSV); its regions are the ABCD A regions of `qcd_est.py` (the BDT `selection.json` thresholds, the ABCD window included, with sentinel values failing, and the `signal_region.csv` score boxes); for k-fold models every event is scored with the model of its fold. A region with fewer than `min_region_events` (10) nominal MC events takes the inclusive ratios and is flagged `fallback_to_inclusive`: with fewer events the ratio measures the MC fluctuation rather than the variation. Missing files, trees, branches, or configured inputs are errors. A config without `signal_region_csv` gives the inclusive ratios only: `config_inclusive.json` in each syst directory writes them to `output/inclusive/`, the input of `mode=3`. `merge_shards.py` in each jet-syst directory merges per-sample SLURM shard outputs.

Other plots: `plotting/sr_sensitivity.py` (`sbatch plotting/submit_sr_sensitivity.sbatch`, config `plotting/config_sr_sensitivity.json`) draws the stacked SR yields of every category with the per-SR significance (`sr_yield_summary.pdf`) and, for selected SRs, stacked MC distributions of chosen variables (N−1 for the cut variables) with optional blinded data from `plotting/submit_sr_sensitivity_data.sbatch`.

Training studies: `selections/BDT/study_boosted3/` holds the boosted3 studies (training variants, per-SR ABCD closure, SR granularity, jet-mass fit) that set the production choices; `significance_review.md` there summarizes them.

Sites (`--site`, default `purdue`):

- `purdue`: the tools are on the `PATH` of the submitting shell, `--slurm` copies `/tmp/x509up_u<uid>` to `/depot/cms/users/$USER/`, and the default account is `cms-express`.
- `fasrc` (FASRC Cannon, Rocky 8 workers): the C++ tools are compiled and run with CMSSW_16_1_0_pre4 (`el9_amd64_gcc13`) inside the CVMFS container `/cvmfs/cms.cern.ch/common/cmssw-el9` through `sites/fasrc/cmssw_exec.sh`, which runs `cmsenv` in the project area `CMSSW_16_1_0_pre4/` at the repository root (create it once with `scram project CMSSW CMSSW_16_1_0_pre4` inside the container); the Python modes run with `pixi run --frozen -e <env> python3` (`--python-env`, `default` = CPU XGBoost, `gpu` = CUDA XGBoost); `combine` (mode 7) runs in the CVMFS image `gitlab-registry.cern.ch/cms-cloud/combine-standalone:latest` (CombinedLimit v11.1.0). The grid proxy is `--x509-proxy` or `$X509_USER_PROXY`, exported to every job as is, and the jobs get no `X509_USER_CERT`/`X509_USER_KEY` (the XRootD TLS client would otherwise try the passphrase-protected user key). `VVV_SCRATCH` must name a scratch directory: `TMPDIR`, `MPLCONFIGDIR`, `XDG_CACHE_HOME`, `PIXI_CACHE_DIR` and `SINGULARITY_CACHEDIR` point below it. With `--slurm` on a login node, `run.py` submits itself as a Slurm job (account `iaifi_lab`): for modes 0, 1, 6, and 2 a small driver job compiles or queries DAS and submits the sample, batch, or per-tree training jobs from a worker (the training jobs run the site's Python); every other mode runs inside the job, which gets the `--slurm-*` resources (for GPU work: `--python-env gpu --slurm-partition iaifi_gpu --slurm-extra=--gres=gpu:1`). Binaries are always built as `{bin_name}_{hash}` and kept. Example: `VVV_SCRATCH=/n/netscratch/... python3 run.py 2 --site fasrc --slurm`.
- `ihep` (IHEP lxlogin and HTCondor workers, AlmaLinux 9; integrated to convert the IHEP-hosted inputs next to the data, kept but no longer used by the current campaign): the C++ tools are compiled (on lxlogin) and run with CMSSW_16_1_0_pre4 (`el9_amd64_gcc13`) natively through `sites/ihep/cmssw_exec.sh`, which runs `cmsenv` in the project area `CMSSW_16_1_0_pre4/` at the repository root and, when the AFS home is not writable, points `HOME` to `build/ihep/home` for `dasgoclient`. `--condor` submits the sample jobs of modes 0, 1, and 6 with `hep_sub` (`--condor-cpus`, `--condor-mem` in MB, `--condor-walltime`); each job is an executable script under `build/condor/jobs/` (stdout/stderr in `build/condor/logs/`) with the explicit proxy, `OMP_NUM_THREADS` and the `--slurm-retries` retry loop. HTCondor jobs have no `afterany` dependency, so mode 0 submits the batch jobs only and the merge is submitted afterwards with `--condor --merge-only`; it fails if any batch is missing, incomplete, or stale. The IHEP batch workers have no outbound network: the mode-0 `--batch-count` DAS query and file-list snapshot run on lxlogin, and mode 1 (whose `weight.C` queries DAS inside the job) cannot run on these workers. Example: `X509_USER_PROXY=<proxy> python3 run.py 0 selections/convert/config_ihep.json --site ihep --condor --condor-cpus 4 --condor-mem 8000 --slurm-files-per-job 20`.

Remote inputs: `convert_branch.C` and `weight.C` read DAS files through `root://cms-xrd-global.cern.ch/` unless the config's optional `remote_input_rules` (list of `{"lfn_prefix", "url_prefix"}`) maps an LFN prefix to another endpoint, e.g. `{"lfn_prefix": "/store/user/yiyangz/", "url_prefix": "root://cceos.ihep.ac.cn//eos/ihep/cms"}` for the IHEP-local XRootD door. The `.files` snapshot and the batch `.meta` input hashes contain the resulting URLs.

Inside a Slurm allocation `run.py` sets `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS` and `MKL_NUM_THREADS` to `SLURM_CPUS_PER_TASK`; `train.py` and `qcd_est.py` size XGBoost threads by the CPUs the process may run on (its CPU affinity), at most 32. `train.py` logs the device every XGBoost stage actually used, and the error when `device=cuda` fails and the stage is rerun on the CPU. SLURM resources: `--slurm-cpus` / `--slurm-mem` default to 32 / 200G for mode 2 and 1 / 4G otherwise; `--slurm-time`, `--slurm-account`, `--slurm-partition`, `--slurm-exclude`, and `--slurm-extra` are passed to `sbatch`.

Sample arguments:

- Extra sample names are supported only for `mode=0`, `mode=1`, and `mode=6`.
- If no sample names are given, `run.py` uses `submit_samples` from the chosen config.
- If `submit_samples` is empty or missing, all MC samples in `src/sample.json` are used.

Log archiving:

- After the final `[finished …]` line is written, `run.py` copies the per-mode `log.txt` into the program's configured output directory for local runs.
- Applies to `mode=1` (`output_root`), `mode=2` / `mode=4` (per-tree `output_root` expanded over `submit_trees`), and `mode=3` / `mode=5` / `mode=7` (`output_dir`). `mode=0` (`convert_branch`) and `mode=6` (`mix`) are intentionally skipped.
- The copy runs on both success and failure; if the resolved output dir does not yet exist (e.g., the run aborted before creating it), the copy is skipped with a warning instead of erroring.

- The syst modes with configs without signal regions write the inclusive ratios read by `mode=3`.
- `mode=3` writes `signal_region.csv`, which defines the A-region score boxes for `mode=5`, the syst modes, and the blinding of `mode=4`.
- `mode=5` writes the ABCD ROOT file and PDFs for the chosen tree.
- `mode=8`, `mode=9`, and `mode=11`–`mode=14` read the converted trees, the trained model (or k-fold models), and `signal_region.csv`, and write the `*_syst_yields.json` ratios read by `mode=7`.

Combined/per-class scenarios use the `groups/*` yields, per-sample scenarios the `samples/*` yields, and the ABCD scenarios replace every QCD class with `qcd_predict` (per-SR ABCD: with the `control/*` and `abcd_bd/*` regions in a control card).

## Generator weights

Every MC weight builder (training and the k-fold score cache, signal regions, QCD ABCD, Data/MC, class-shape and sensitivity plots, the JMS/JMR fit, and the theory, pileup, and jet systematics) uses signed, absolutely normalized event weights, implemented once in `selections/mc_weight_common/mc_weights.py`:

    w = lumi × xsection × genWeight × weight_pu / S × N_tree / N_read

- `S`: the sum of `genWeight × weight_pu` over every processed generated event of the sample, before any selection, written as `sum_genweight_pu` into `src/sample.json` by the convert merge (together with `sum_genweight` and the pileup-variation sums `sum_genweight_pu_up` / `sum_genweight_pu_down`). The selected events therefore carry the selection efficiency, and the NLO samples (VV about 20% negative weights, VVV about 5%, qq→VH about 3%, ttbar 0.4%) enter with signed weights. A sample without a positive `S` stops every weight builder with an error.
- `N_tree / N_read`: scales a read subset (a train/eval/test split or a capped read) to the whole tree; 1 for full reads (k-fold score cache, systematics, data/MC plots).
- Configs list the product as `event_reweight_branches: ["genWeight", "weight_pu"]`; the jet-variation trees carry `genWeight` (`variation_branches`).
- Pileup systematics normalize each variation by its own sum (`pu_up = [Σ g·pu_up / S_up] / [Σ g·pu / S]`); theory systematics are acceptance ratios, each variation normalized to its value over all generated events (mode 8), while the inclusive cross-section uncertainties enter combine as `xsec_<process>`.
- The classifier is trained with `|w| × Σw / Σ|w|` per sample and split (XGBoost accepts only non-negative weights); a sample whose signed sum in a split is not positive gets zero training weight with a warning. All physics outputs use the signed weights.
- `selections/BDT/gen_weight.py` (the former `genWeight / genweight_mean` normalization) is no longer used by any script; `genweight_mean` remains a cross-check of `sum_genweight / raw_entries`.

## Jet energy corrections

`convert_branch.C` (`JetPtCorrector`) corrects the AK4 `ScoutingPFJetRecluster2` and AK8 `ScoutingFatPFJetRecluster` jets (plain PF jets, neither CHS nor PUPPI, matching AK4PFHLT/AK8PFHLT) and the MET before any selection or output reads an event. The `jet_pt_correction` block of the convert config configures it.

- **JEC (MC and data):** the official HLT MC-truth JEC `Winter24HLT_V1_MC_L1L2L3Res_{AK4,AK8}PFHLT` ([JECDatabase](https://github.com/cms-jet/JECDatabase/tree/master/textFiles/Winter24HLT_V1_MC)); there is no residual (data/MC) correction (`L2L3Residual` returns 1.0), and the JERC group recommends these JECs for the 2024 simulation and the 2024CDEFGHI data. The JSON files are copied from `/eos/cms/store/group/phys_jetmet/ExpJEC/json_files_HLT/Run3Winter24/` into `selections/convert/jec/Run3Winter24/`. The AK4 inputs already carry this JEC from the ScoutingNano production (raw = stored × (1 − `rawFactor`) for pT and mass), so the stored AK4 pT and mass are the nominal JEC result; the AK8 inputs are stored raw and get the JEC.
- **Event rho:** the inputs do not store rho, so it is recovered from the AK4 production JEC: stored / raw = C(JetA, JetEta, JetPhi, raw pT, rho) falls with rho up to the L1FastJet clamp at 70 GeV, one jet gives rho, and every AK4 jet must reproduce its stored factor within 0.5 GeV of it (a jet whose stored eta or phi lies on a JEC bin edge may use the neighbouring bin). An event whose AK4 jets have no common rho stops the conversion with an error naming the event. On the v4 data, which store `ScoutingRho_fixedGridRhoFastjetAll`, recovered − true rho has a mean of −0.004 GeV and an RMS of 0.018 GeV, without failure in 20000 events.
- **JER (MC):** the offline proxy `Summer23BPixPrompt23_RunD_JRV1_MC_{PtResolution,ScaleFactor}_AK4PFPuppi` (JME-POG `2024_Summer24/jet_jerc.json.gz`) with the stochastic `JERSmear` tool (`jer_smear.json.gz`, `GenPt = −1`), for AK4 and AK8 alike: CMS provides no JER for scouting jets and none for AK8. The nominal MC is smeared with the `nom` scale factor. The resolution lookup clamps rho below 52.05, the end of its Rho axis. JERSmear draws its random number from (JetPt, JetEta, Rho, EventID), which are the same in every configuration, so `jer_up` / `jer_down` change only the scale factor. Data are not smeared.
- **JES uncertainty (MC):** a flat ±10% per jet (`jes_shift`) on pT, mass, and soft-drop mass after the JER smearing, one nuisance for AK4 and AK8 (fully correlated). Source: the JERC recommendation for scouting jets quotes the closure of the online HLT JECs on scouting jets as "within < 2% for `ScoutingPFJet` and within < 5-10% for `ScoutingPFJetRecluster`" (presentations: https://indico.cern.ch/event/1661768/, https://indico.cern.ch/event/1667359/); both our collections are reclustered, and 10% is the upper edge. The value covers only the non-closure of the MC-truth correction: residual (data/MC) corrections are neither applied nor covered, and CMS gives no closure for scouting AK8 jets, so using the same value for AK8 is our choice.
- **AK8 soft-drop mass:** every factor of the jet pT except L1FastJet (grooming removes most of the pileup), i.e. L2L3, the JER smearing, and the JES shift, and, for MC with `apply_jms_jmr`, the CMS-standard JMS scale and stochastic JMR smearing `m × JMS × (1 + N(0,1) × sqrt(max(JMR² − 1, 0)) × σ_MC/μ_MC)` (no smearing for JMR ≤ 1), with JMS, JMR, and the MC W-peak width σ_MC/μ_MC from `selections/jms_jmr/output/jms_jmr_results.json`. The checked-in fit predates these corrections (JMS = 1.071, +7% on the MC soft-drop mass; JMR = 0.52); re-measure it from the corrected ttbar control region.
- **Type-1 MET:** MET = raw MET − Σ (corrected − L1FastJet-only) muon-subtracted pT (muon fraction `muEF`) over the AK4 jets whose corrected, unsmeared, muon-subtracted pT is above 15 GeV and whose EM fraction `chEmEF + neEmEF` is below 0.9. The JER and JES variations move the MET through the same jets.

**Single pass, variation trees.** Each MC event is read once and corrected with the nominal configuration and each of the `variations` (`jes_up`, `jes_down`, `jer_up`, `jer_down`, `jms_up`, `jms_down`, `jmr_up`, `jmr_down`). Every configuration rebuilds the collections, re-applies the tree selections, and fills `<tree>__<variation>` trees in the same output file. A variation tree books the `variation_branches` list of its tree (the BDT features, thresholds, and decorrelation branches plus `run`, `luminosityBlock`, `event`, `genWeight`, `weight_pu`) and evaluates only the scalar outputs those branches depend on. The variation trees are identical, event by event, to the nominal trees of a conversion with `debug_nominal_configuration` set to that variation (a validation setting that fills the nominal trees with one configuration). Data get the nominal configuration only.

**Keys.** `enabled`, `nominal_correction` (`hlt_jec`, or the legacy `scouting_to_offline` response SF of `corrections_file` with `ak4_tag_threshold` / `ak8_tag_threshold`), `jec_ak4_file`, `jec_ak8_file`, `jec_ak4_name`, `jec_ak8_name`, `jec_ak4_l1_name`, `jec_ak8_l1_name`, `jes_jer_file`, `jer_smear_file`, `jer_resolution_name`, `jer_scale_factor_name`, `jes_shift`, `apply_jms_jmr`, `jms_jmr_results_file`, `variations`, `variation_branches`, and `debug_nominal_configuration`. The keys `variation`, `jes_unc_name`, and `jer_rho_fallback` of the removed one-variation-per-conversion scheme are rejected; `selections/convert/config_{jes,jer}_{up,down}.json` are kept for reference only. The event preselection runs before the corrections on input scalars and must not read `ScoutingMET_pt` / `ScoutingMET_phi`. `variation_branches` must list, per tree, every BDT feature (`selections/BDT/branch.json`), threshold branch (`selection.json`), and decorrelation branch (`config.json` `decorrelate`) of the trained model, plus `run`, `luminosityBlock`, `event`, `genWeight`, and `weight_pu`; after a change of the BDT inputs, update it (the jet syst scripts stop with an error naming a missing branch).

**Cost.** On one QCD HT1500–2000 file (about 200k preselected events) the corrections add about 12% CPU to a nominal-only conversion (7% for data), and the eight MC variation configurations bring the total to about 4.2 times the nominal-only conversion: each variation costs about 40% of a separate conversion, because the input is read once and the variation trees evaluate only their needed outputs. Runtime collections independent of the jet corrections (the GenPart-based `w_quarks`, `wz_had_quarks`) are built once per event (logged at startup). Plan the MC conversion jobs for that CPU time.

**Environment.** `convert_branch.C` builds in the CMSSW_16_1_0_pre4 (`el9_amd64_gcc13`) environment with CMSSW's correctionlib 2.7.0. `run.py` locates correctionlib through `python3 -c "import correctionlib"`, so a user-site copy (`~/.local/lib/python3.9/site-packages/correctionlib`) takes precedence over CMSSW's; check `python3 -c "import correctionlib; print(correctionlib.__version__)"` before building.

## Systematic uncertainties

`combine.C` fits the Asimov pseudo-data (the sum of the nominal process rates, `-t -1`). Every channel card contains:

| Nuisance | Type, value | Processes | Correlation |
|---|---|---|---|
| `lumi` | lnN 1.016 (`lumi_unc`) | MC processes | all processes, SRs, and channels |
| `trigger` | lnN 1.03 (`trigger_unc`), a flat value set by the user; no trigger scale factor is measured | MC processes | all |
| `xsec_<process>` | lnN 1 + the yield-weighted mean of its samples' cross-section uncertainties (`xsec_unc_json`, sample-name patterns; `combine/xsec_unc.json` holds the proposed values with their sources) | MC processes | all SRs and channels; independent between processes |
| `pileup` | lnN from `weight_pu_up` / `weight_pu_down` (mode 9) | MC processes | all |
| `theory_pdf` | lnN, symmetric-Hessian PDF (+ αs when stored) acceptance spread (mode 8) | MC processes; samples without theory weights count with ratio 1 | all |
| `theory_scale_<process>` | lnN, 7-point μR/μF acceptance envelope (mode 8) | as `theory_pdf` | all SRs and channels; independent between processes |
| `theory_ps_isr`, `theory_ps_fsr` | lnN, parton-shower `murfac` 0.5 (up) and 2.0 (down) (mode 8) | as `theory_pdf` | all |
| `jes` | lnN, flat ±10% per jet (mode 11) | MC processes | all |
| `jer` | lnN, JER scale factor up/down (mode 12) | MC processes | all |
| `jms` | lnN, JMS ± its uncertainty (mode 13) | MC processes | all |
| `jmr` | lnN, JMR ± its uncertainty (mode 14; no effect while JMR ± σ ≤ 1) | MC processes | all |
| MC statistics (`autoMCStats`) | `* autoMCStats 10` (`mc_stat_threshold`) from the template errors `sqrt(sum w^2)` (combine's default excludes the signal) | all processes | per bin |
| zero-count floor (`zero_count_floor`) | `gmN 0 α` per SR and background class without MC events, α = the class's median event weight, started at 0 | background classes (`combined` / `class` scenarios) and the union-mode ABCD QCD | per SR and process |
| `qcd_abcd_nonclosure_<channel>` | lnN; per-SR ABCD: 1 + `abcd_per_sr_nonclosure` (0.2); union ABCD: 1 + \|1 − closure\| | `bkg_qcd` | all SRs of the channel |
| `qcd_abcd_stat_<channel>` | union ABCD only: lnN 1 + the B/C/D MC-statistics uncertainty of the ABCD scale | `bkg_qcd` | all SRs of the channel |
| per-SR ABCD control-region fit | free rateParams `qcdC_<channel>_sr<N>` (each control region `C_i`) and `qcdB_<channel>`, `qcdD_<channel>`; the SR QCD is `C_i × B/D` | `bkg_qcd` | constrained by the control-region counts |

With the per-SR ABCD (`qcd_est.py` `abcd_mode: per_sr`), a second card per channel holds the control regions `C_i` and the ABCD regions B and D with the same processes. `lumi`, `trigger` and `xsec_<process>` act on its `C_i` bins but not on B and D, where the non-QCD MC is subtracted at its nominal yield: in these regions of up to ~1e9 events the free QCD normalisations otherwise had to follow those nuisances to ~3e-5, which broke the fits, while a 15% normalisation change moves the QCD transfer factor B/D by at most 0.5%. The control card carries no per-SR ratio rows.

The theory ratios are normalised to the generated events (mode 8 above), so they change only the selection efficiency; the inclusive cross-section uncertainties enter as `xsec_<process>`. The per-sample ratios come from the syst scripts (per SR; regions with fewer than 10 MC events take the inclusive ratio). A process kappa in an SR is the mean of its samples' ratios weighted by their SR yields in the `qcd_est.py` output; asymmetric kappas are written `κ_down/κ_up`. A non-positive kappa (a variation removing the whole yield) is an error. The MC-based nuisances do not act on the ABCD prediction `bkg_qcd`, which takes the ABCD rows instead; in the MC-true scenarios the QCD class is an MC process with every MC nuisance.

Not included:

- Residual (data/MC) JEC and its uncertainty, and a JES split into sources: no HLT residuals exist for scouting jets.
- A scouting or AK8 JER, and the hybrid (gen-matched) JER smearing: only the offline AK4PFPuppi proxy exists, and GenJetAK8 is available only in the `jetMatchFix` samples.
- The unclustered-energy MET uncertainty: the Type-1 MET propagates only the jet corrections and their variations.
- Jet-tagging scale factors (the AK8 ParT W/V tagging and the AK4 b-veto): none exist for scouting jets.
- Lepton identification, isolation, and veto efficiencies.
- Data statistics of the ABCD regions: the study fits Asimov data built from MC; with data, the observed control-region counts constrain the per-SR ABCD.
